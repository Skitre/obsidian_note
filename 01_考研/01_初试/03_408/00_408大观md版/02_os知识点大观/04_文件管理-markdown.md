# 第 4 章 文件管理
## 4.1    文件系统基础
### 4.1.1   文件的基本概念 
- 文件 (File) 定义

- 文件组成要素
  - 存储空间中的数据
  - 分类和索引信息
  - 访问权限信息
- 图书馆类比
  - 文件 ↔ 图书
  - 文件数据 ↔ 书的内容
  - 文件分类 ↔ 图书分类编号
  - 访问权限 ↔ 借阅权限
- 文件系统功能
  - 提供二级存储抽象
  - 方便用户使用文件
- 文件结构（自底向上）
  - 数据项
    - 基本数据项
    - 组合数据项
  - 记录
  - 文件
    - 有结构文件
    - 无结构文件
- 文件属性
  - 名称
  - 类型
  - 创建者
  - 所有者
  - 位置
  - 大小
  - 保护
  - 时间信息（创建/修改/访问）
- 文件分类
  - 按性质和用途
    - 系统文件
    - 用户文件
    - 库文件
  - 按数据形式
    - 源文件
    - 目标文件

  - 按存取控制属性
    - 可执行文件
    - 只读文件

  - 按组织形式和处理方式
    - 普通文件
    - 目录文件
    - 特殊文件

### 4.1.2   文件控制块和索引节点 
- ①. 文件控制块(FCB)
  - 定义
    - 数据结构：File Control Block
    - 功能：实现按名存取
  - 特点
    - 文件与FCB一一对应
    - FCB集合=文件目录
    - 单个FCB=目录项
    - 目录文件：文件目录的存储形式
  - 包含信息
    - 基本信息
      - 文件名
      - 物理位置
      - 逻辑结构
      - 物理结构
    - 存取控制信息
      - 文件主权限
      - 核准用户权限
      - 普通用户权限
    - 使用信息
      - 创建时间
      - 最后修改时间
- ②. 索引节点(inode)
  - 背景问题
    - 传统FCB缺陷
      - 目录存储占用大量磁盘块
      - 检索时仅需文件名
  - UNIX解决方案
    - 结构分离
      - 目录项精简为：
        - 文件名
        - inode编号/指针
      - 详细描述信息→独立inode
  - 性能对比
    - FCB方案(64B)
      - 1KB盘块存储16个FCB
      - 640文件需20次磁盘访问
    - UNIX方案(16B目录项)
      - 1KB盘块存储64项
      - 磁盘访问减少75%
  - 类型分类
    - (1)磁盘索引节点
      - 存储位置：磁盘
      - 特性：唯一性
      - 包含字段
        - 文件主ID
        - 文件类型
        - 权限
        - 物理地址(iaddr[0-12])
        - 文件长度
        - 链接计数
        - 时间戳
    - (2)内存索引节点
      - 存储位置：内存
      - 激活条件：文件打开时
      - 扩展字段
        - inode编号
        - 状态标志
        - 访问计数
        - 设备号
        - 链表指针

### 4.1.3   文件的操作 
- ①. 文件的基本操作
  - 文件属于抽象数据类型
  - 操作系统提供系统调用实现文件操作
    - 创建文件
      - 为新文件分配外存空间
      - 在目录中创建目录项
        - 记录文件名
        - 记录外存地址
    - 删除文件
      - 根据文件名查找目录
      - 删除目录项和文件控制块
      - 回收存储空间
    - 读文件
      - 根据文件名查找目录
      - 从目录项获取外存地址
      - 使用读指针操作文件
    - 写文件
      - 根据文件名查找目录
      - 使用写指针操作文件
      - 更新写指针
- ②. 文件的打开与关闭
  - 打开文件
    - 首次操作前需调用open
    - 系统维护打开文件表
      - 目录项从外存复制到内存
      - 返回文件描述符
  - 关闭文件
    - 调用close
    - 删除打开文件表条目
  - 两级表结构
    - 系统表
      - 包含与进程无关的信息
        - 磁盘位置
        - 访问日期
        - 文件大小
    - 进程表
      - 包含进程使用信息
        - 当前读/写指针
        - 访问权限
        - 指向系统表指针
    - 打开计数器
      - 记录打开进程数
      - 为0时删除系统表条目
  - 文件描述符
    - UNIX:文件描述符
    - Windows:文件句柄
    - 操作通过描述符进行
  - 打开文件关联信息
    - 文件指针
      - 记录上次读/写位置
      - 对进程唯一
    - 文件打开计数
      - 跟踪打开/关闭次数
    - 文件磁盘位置
      - 保存在内存中
      - 避免每次从磁盘读取
    - 访问权限
      - 保存在进程打开文件表
      - 决定后续I/O请求
### 4.1.4   文件保护 
- 定义
  - 用户角度看到的文件组织形式
  - 与存储介质特性无关
- 分类
  - 无结构文件（流式文件）
    - 特点
      - 由字符流构成
      - 长度以字节为单位
      - 通过读/写指针访问
    - 应用场景
      - 源程序
      - 可执行文件
      - 库函数
    - 缺点
      - 只能穷举搜索访问
  - 有结构文件（记录式文件）
    - 记录类型
      - 定长记录
        - 特点：所有记录长度相同
        - 优点：检索速度快
      - 变长记录
        - 特点：记录长度不同
        - 缺点：只能顺序查找
    - 组织形式
      - 顺序文件
        - 结构类型
          - 串结构：按存入时间排列
          - 顺序结构：按关键字排列
        - 特点
          - 批量操作效率高
          - 适合顺序存储设备（如磁带）
        - 缺点
          - 单记录操作性能差
      - 索引文件
        - 组成
          - 主文件
          - 索引表（含指针和记录长度）
        - 优点
          - 变随机检索为顺序检索
          - 加快检索速度
        - 缺点
          - 增加存储开销
      - 索引顺序文件
        - 特点
          - 顺序文件+索引文件的结合
          - 使用一级索引
        - 查找过程
          ①. 查找索引表确定组
          ②. 在组内顺序查找
        - 效率
          - 平均查找次数：√N
        - 扩展
          - 可采用多级索引
      - 直接文件/散列文件（Hash File）
        - 特点
          - 键值直接决定物理地址
          - 存取速度高
        - 问题
          - 可能引起冲突

### 4.1.6   文件的物理结构 
- 文件分配方式
  - 连续分配
    - 优点
      - 支持顺序访问和直接访问
      - 顺序访问容易且速度快
    - 缺点
      - 产生外部碎片
      - 需事先知道文件长度
      - 插入删除记录需物理移动
  - 链接分配
    - 优点
      - 消除外部碎片
      - 便于动态分配
      - 插入删除修改方便
    - 形式
      - 隐式链接
        - 缺点
          - 只支持顺序访问
          - 稳定性问题
          - 指针占用存储空间
        - 改进
          - 按簇分配
      - 显式链接
        - FAT表
          - 优点
            - 支持顺序和直接访问
            - 检索速度快
          - 缺点
            - 占用内存空间
  - 索引分配
    - 单级索引分配
      - 优点
        - 支持直接访问
        - 无外部碎片
      - 缺点
        - 索引块额外开销
        - 小文件利用率低
    - 多级索引分配
      - 优点
        - 加快大型文件查找
      - 缺点
        - 访问磁盘次数增加
    - 混合索引分配
      - UNIX系统inode结构
        - 直接地址
          - 小文件
        - 一次间接地址
          - 中型文件
        - 多次间接地址
          - 大型文件

## 4.2    目录 
### 4.2.1    目录的基本概念 
- 基本概念

  - 多用户支持

  - 允许文件名重复

- 目录结构
  - 树形目录结构
    - 解决命名冲突问题
    - 便于用户按习惯命名

### 4.2.5    文件共享
- 文件共享概念
  - 多个用户共享同一个文件
  - 系统中只需保留一个副本
  - 避免存储空间浪费
- 实现方式
  - 基于无环图目录结构
    - 建立链接关系时复制物理地址
    - 新增数据仅对操作者可见
  - ①. 基于索引节点的共享方式（硬链接）
    - 原理
      - 文件物理地址和属性放在索引节点
      - 目录项只含文件名和索引节点指针
      - 引用计数count表示共享用户数
    - 特点
      - 文件主删除文件时count减1
      - 当count=0时才真正删除文件
  - ②. 利用符号链实现文件共享（软链接）
    - 原理
      - 创建LINK类型文件记录路径名
      - 类似Windows快捷方式
    - 特点
      - 只有文件主拥有索引节点指针
      - 删除共享文件后访问失败
      - 需要多次读盘，开销较大
- 比较
  - 硬链接
    - 多个指针指向一个索引节点
    - 查找速度快
  - 软链接
    - 保存文件路径
    - 查找速度较慢

## 4.3    文件系统
### 4.3.1   文件系统结构 
- 文件系统 (File system)  
  - 功能  
    - 提供高效和便捷的磁盘访问  
    - 允许存储、定位、提取数据  
  - 设计问题  
    - 用户接口  
      - 定义文件及其属性  
      - 允许的文件操作  
      - 组织文件的目录结构  
    - 算法和数据结构  
      - 映射逻辑文件系统到物理外存设备  
- 文件系统层次结构  
  - I/O 控制层  
    - 组成  
      - 设备驱动程序  
      - 中断处理程序  
    - 功能  
      - 在内存和磁盘系统之间传输信息  
      - 翻译命令为硬件指令  
      - 控制I/O设备与系统交互  
  - 基本文件系统  
    - 功能  
      - 发送通用命令读写物理块  
      - 管理内存缓冲区  
      - 保存文件系统、目录和数据块的缓存  
      - 分配和管理缓冲区  
  - 文件组织模块  
    - 功能  
      - 组织文件及其逻辑块和物理块  
      - 逻辑块地址转换为物理块地址  
      - 管理空闲空间  
        - 跟踪未分配的块  
        - 根据需求分配块  
  - 逻辑文件系统  
    - 功能  
      - 管理元数据信息

### 4.3.2    文件系统布局 
- 文件系统在磁盘中的结构
  - 文件系统存放在磁盘上，多数磁盘划分为一个或多个分区
  - 每个分区中有一个独立的文件系统
  - 文件系统可能包括的信息
    - 启动存储在那里的操作系统的方式
    - 总的块数
    - 空闲块的数量和位置
    - 目录结构
    - 各个具体文件
  - 可能的文件系统布局描述
    - 主引导记录(MBR)
      - 位于磁盘的0号扇区
      - 用来引导计算机
      - MBR后面是分区表
        - 给出每个分区的起始和结束地址
        - 一个分区被标记为活动分区
      - 计算机启动时，BIOS读入并执行MBR
      - MBR确定活动分区，读入它的第一块（引导块）
    - 引导块(boot block)
      - MBR执行引导块中的程序
      - 该程序负责启动该分区中的操作系统
      - 每个分区都从引导块开始
      - Windows系统称之为分区引导扇区
    - 超级块(super block)
      - 包含文件系统的所有关键信息
      - 在计算机启动或文件系统首次使用时读入内存
      - 典型信息包括
        - 分区的块的数量
        - 块的大小
        - 空闲块的数量和指针
        - 空闲的FCB数量和FCB指针
    - 文件系统中空闲块的信息
      - 可以用位示图或指针链接的形式给出
    - 后面可能跟的是一组i节点
      - 每个文件对应一个节点
      - i节点说明文件的方方面面
    - 接着可能是根目录
      - 存放文件系统目录树的根部
    - 磁盘的其他部分存放了其他所有的目录和文件
- 文件系统在内存中的结构
  - 内存中的信息用于管理文件系统并通过缓存来提高性能
  - 这些数据在安装文件系统时被加载，操作期间被更新，卸载时被丢弃
  - 结构类型可能包括
    - 内存中的安装表(mount table)
      - 包含每个已安装文件系统分区的有关信息
    - 内存中的目录结构的缓存
      - 包含最近访问目录的信息
    - 整个系统的打开文件表
      - 包含每个打开文件的FCB副本
      - 打开计数及其他信息
    - 每个进程的打开文件表
      - 包含进程打开文件的文件描述符（Windows称之为文件句柄）
      - 指向整个系统的打开文件表中对应表项的指针
### 4.3.3    外存空闲空间管理 
- 卷(volume)
  - 定义
    - 包含文件系统的分区
    - 可以是磁盘的一部分、整个磁盘或多个磁盘组成的RAID集
  - 初始化
    - 划分目录区和文件区
    - 建立空闲空间管理表格
    - 存放卷信息的超级块
- 空闲块管理方法
  - 空闲表法
    - 特点
      - 连续分配方式
      - 类似内存的动态分区分配
    - 实现
      - 空闲表结构
        - 表项序号
        - 第一个空闲盘块号
        - 空闲盘块数
      - 分配算法
        - 首次适应算法
        - 最佳适应算法
    - 优缺点
      - 优点：分配速度快，减少I/O频率
      - 缺点：仅适合小文件(1-5个盘块)
  - 空闲链表法
    - 空闲盘块链
      - 实现
        - 以盘块为单位链接
        - 每个盘块有指向下一个空闲盘块的指针
      - 优缺点
        - 优点：分配回收简单
        - 缺点：效率低，链过长
    - 空闲盘区链
      - 实现
        - 以盘区为单位链接
        - 每个盘区包含指向下一个空闲盘区的指针和盘块数
        - 采用首次适应算法
      - 优缺点
        - 优点：效率高，链较短
        - 缺点：分配回收复杂
  - 位示图法
    - 实现
      - 二进制位表示盘块使用情况
      - 0表示空闲，1表示已分配
    - 盘块号计算
      - 分配时：b=n(i-1)+j
      - 回收时：
        - i=(b-1)DIV n+1
        - j=(b-1)MOD n+1
    - 优缺点
      - 优点：容易找相邻空闲块，占用空间小
      - 缺点：位示图随磁盘容量增大而增大
  - 成组链接法
    - 实现
      - 空闲盘块分组(如每组100个)
      - 每组的第一个盘块记录下一组信息
      - 第一组信息保存在内存的专用栈中
    - 分配过程
      - 从栈中分配盘块
      - 栈底时读取下一组信息到栈
    - 回收过程
      - 盘块号存入栈顶
      - 栈满时将100个盘块号存入新回收盘块
    - 特点
      - 结合空闲表法和空闲链表法
      - 克服了它们的缺点
### 4.3.4    虚拟文件系统 
- 定义
  - 屏蔽不同文件系统的差异和操作细节
  - 提供统一调用接口
- 特点
  - 采用面向对象思想
  - 抽象通用文件系统模型
  - 定义通用接口
- 四种对象类型
  - 超级块对象
    - 表示已安装的文件系统
    - 存储元信息
    - 操作方法
      - 分配inode
      - 销毁inode
      - 读inode
      - 写inode
  - 索引节点对象
    - 表示特定文件
    - 一对一关系
    - 操作函数
      - 创建新索引节点
      - 创建硬链接
      - 创建新目录
  - 目录项对象
    - 表示特定目录项
    - 包含指针
      - 关联索引节点
      - 父目录
      - 子目录
  - 文件对象
    - 表示已打开文件
    - 包含内容
      - 目录项对象
      - 文件系统
      - 文件指针
      - 操作函数
- 工作原理
  - 系统调用流程示例
    - write()调用
      - sys_write()处理
      - 调用具体文件系统写方法
      - 与物理介质交互
- 特性
  - 对用户透明
  - 仅存在于内存
  - 系统启动时建立
  - 系统关闭时消亡

### 4.3.5    文件系统挂载 
- 定义
  - 文件系统在使用前必须先安装/挂载(Mounting)
- 挂载原理
  - 将设备文件系统挂载到目录后通过该目录访问设备文件
  - 设备指逻辑设备（如磁盘不同分区）
- Windows系统实现
  - 维护扩展的两级目录结构
    - 驱动器字母表示设备和卷
    - 卷具有常规树结构目录
  - 文件路径格式：driver-letter:\path\to\file
  - 新版支持任意位置挂载（类似UNIX）
  - 启动时自动发现并安装所有文件系统
- UNIX系统实现
  - 根文件系统
    - 系统启动时直接安装
    - 包含内核映像
  - 其他文件系统
    - 必须挂载到根文件系统目录
    - 安装点特性
      - 同一设备可有多个安装点
      - 同一安装点同时只能挂载一个设备
  - 挂载命令示例
    - mount -t ext2 /dev/fd0 /flp
  - 卸载命令：umount
