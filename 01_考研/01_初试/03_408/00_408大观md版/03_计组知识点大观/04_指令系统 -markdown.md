# 第 4 章 指令系统 
## 4.1   指令系统 
### 4.1.2    指令的基本格式 
- 指令组成
  - 操作码字段
    - 功能：识别指令、了解功能、区分操作数地址
    - 示例：算术运算、程序转移等
  - 地址码字段
    - 功能：给出被操作信息的地址
    - 包括：操作数地址、结果保存地址、程序转移地址等
- 指令字长
  - 定义：指令包含的二进制代码位数
  - 决定因素：操作码长度、地址码长度和个数
  - 与机器字长的关系
    - 单字长指令：等于机器字长
    - 半字长指令：等于半个机器字长
    - 双字长指令：等于两个机器字长
  - 取指令时间开销
    - 单字长：1次访存
    - 双字长：2次访存
  - 指令字结构
    - 定长指令字结构：所有指令长度相等
    - 变长指令字结构：指令长度随功能变化
- 指令格式分类
  - 零地址指令
    - 特点：只有操作码，无显式地址
    - 两种可能
      - 不需要操作数的指令（如空操作、停机等）
      - 堆栈计算机中的运算类指令
  - 一地址指令
    - 两种形态
      - 单操作数指令：OP(A₁)→A₁
      - 双操作数指令：(ACC)OP(A₁)→ACC
    - 示例：加1、减1、求反等
    - 寻址范围示例
      - 32位指令（8位操作码+24位地址码）：16M
      - 访存次数：3次
  - 二地址指令
    - 指令含义：(A₁)OP(A₂)→A₁
    - 示例：算术和逻辑运算指令
    - 寻址范围示例
      - 32位指令（8位操作码+2×12位地址码）：4K
      - 访存次数：4次
  - 三地址指令
    - 指令含义：(A₁)OP(A₂)→A₃
    - 寻址范围示例
      - 32位指令（8位操作码+3×8位地址码）：256
      - 访存次数：4次
  - 四地址指令
    - 指令含义：(A₁)OP(A₂)→A₃, A₄=下条指令地址
    - 寻址范围示例
      - 32位指令（8位操作码+4×6位地址码）：64
      - 访存次数：4次
### 4.1.3    定长操作码指令格式 
- 特点
  - 在指令字的最高位部分分配固定的若干位表示操作码
  - 操作码字段长度固定
- 计算公式
  - n位操作码字段可表示2^n条指令
- 优势
  - 简化计算机硬件设计
  - 提高指令译码速度
  - 提高指令识别速度
### 4.1.4    扩展操作码指令格式 
- 基本概念
  - 在指令字长有限的前提下保持丰富指令种类
  - 采用可变长度操作码
    - 操作码字段位数不固定
    - 分散在指令字不同位置
    - 增加指令译码和分析难度
    - 使控制器设计复杂化
- 扩展操作码方法
  - 操作码长度随地址码减少而增加
  - 不同地址数指令具有不同长度操作码
  - 有效缩短指令字长
  - 分配方案
    - 三地址指令15条
      - 1111留作扩展
    - 二地址指令15条
      - 11111111留作扩展
    - 一地址指令15条
      - 111111111111留作扩展
    - 零地址指令16条
- 其他扩展方法示例
  - 15条三地址指令
  - 12条二地址指令
  - 63条一地址指令
  - 16条零地址指令
  - 共106条指令
- 设计注意事项
  - 1)不允许短码是长码的前缀
    - 短操作码不能与长操作码前面部分代码相同
  - 2)各指令操作码不能重复
- 优化原则
  - 高频指令分配较短操作码
  - 低频指令分配较长操作码
  - 减少指令译码和分析时间
### 4.1.5    指令的操作类型 
- 数据传送
  - 寄存器之间的传送 (MOV)
  - 从内存单元读取数据到CPU寄存器 (LOAD)
  - 从CPU寄存器写数据到内存单元 (STORE)
  - 进栈操作 (PUSH)
  - 出栈操作 (POP)
- 算术和逻辑运算
  - 加 (ADD)
  - 减 (SUB)
  - 乘 (MUL)
  - 除 (DIV)
  - 加1 (INC)
  - 减1 (DEC)
  - 与 (AND)
  - 或 (OR)
  - 取反 (NOT)
  - 异或 (XOR)
- 移位操作
  - 算术移位
  - 逻辑移位
  - 循环移位
- 转移操作
  - 无条件转移 (JMP)
  - 条件转移 (BRANCH)
  - 调用 (CALL)
  - 返回 (RET)
  - 陷阱 (TRAP)
- 输入输出操作
  - CPU与外部设备交换数据
  - 传送控制命令及状态信息
## 4.2   指令的寻址方式 
### 4.2.1    指令寻址和数据寻址 
- 指令寻址
  - 顺序寻址
    - 通过程序计数器PC加1自动形成下一条指令的地址
    - PC自增大小与编址方式、指令字长的关系
      - 按字节编址
        - 指令字长为16位：PC自增为(PC)+2
        - 指令字长为32位：PC自增为(PC)+4
  - 跳跃寻址
    - 通过转移类指令实现
    - 是否跳跃可能受到状态寄存器的控制
    - 跳跃方式
      - 绝对转移：地址码直接指出转移目标地址
      - 相对转移：地址码指出转移目的地址相对于当前PC值的偏移量
- 数据寻址
  - 指令格式中各字段的位数分析
    - 操作码
    - 寻址特征
      - 位数决定了寻址方式的种类
    - 形式地址A
      - 形式地址结合寻址方式可计算出有效地址(EA)
      - 不同寻址方式下形式地址的作用
        - 立即寻址：形式地址的位数决定操作数的范围
        - 直接寻址：形式地址的位数决定可寻址的范围
        - 寄存器寻址：形式地址的位数决定通用寄存器的最大数量
        - 寄存器间接寻址：寄存器的位数决定可寻址的范围
### 4.2.2    常见的数据寻址方式
- ①. 隐含寻址
  - 定义：指令不明显给出操作数地址，而是隐含操作数地址
  - 优点：缩短指令字长
  - 缺点：需增加存储操作数或隐含地址的硬件
- ②. 立即(数)寻址
  - 定义：地址字段指出的是操作数本身（立即数）
  - 优点：指令执行阶段不访存，执行速度最快
  - 缺点：立即数范围受限
- ③. 直接寻址
  - 定义：形式地址A就是操作数的真实地址EA（EA=A）
  - 优点：简单，仅需访存一次
  - 缺点：寻址范围受限，操作数地址不易修改
- ④. 间接寻址
  - 定义：地址字段给出的是操作数地址的地址（EA=(A)）
  - 优点：扩大寻址范围，便于编制程序
  - 缺点：需多次访存（一次间接寻址需2次访存）
- ⑤. 寄存器寻址
  - 定义：地址字段给出操作数所在寄存器的编号（EA=R）
  - 优点：执行速度快，指令字长短
  - 缺点：寄存器数量有限
- ⑥. 寄存器间接寻址
  - 定义：寄存器给出操作数所在主存单元的地址（EA=(R)）
  - 特点：扩大寻址范围，减少访存次数（仅需访存1次）
- ⑦. 相对寻址
  - 定义：EA=(PC)+A（A为相对于PC的偏移量）
  - 优点：便于程序浮动
  - 应用：广泛应用于转移指令
- ⑧. 基址寻址
  - 定义：EA=(BR)+A（BR为基址寄存器）
  - 特点：基址寄存器内容由操作系统确定，形式地址可变
  - 优点：扩大寻址范围，有利于多道程序设计
- ⑨. 变址寻址
  - 定义：EA=(IX)+A（IX为变址寄存器）
  - 特点：变址寄存器内容由用户设定，形式地址不变
  - 优点：适合编制循环程序，处理数组问题
- ⑩. 堆栈寻址
  - 定义：使用堆栈指针(SP)管理按LIFO原则的存储区
  - 类型：
    - 硬堆栈（寄存器堆栈）
    - 软堆栈（主存中划出的区域）
  - 特点：操作数地址隐含使用SP

  - if-then-else

  - 编译器通过条件码(标志位)设置指令和各类转移指令实现
- 条件码
  - 描述最近的算术或逻辑运算操作属性
  - 常用条件码
    - CF
    - ZF
    - SF
    - OF
- 设置条件码的指令
  - 算术逻辑运算指令
    - add
    - sub
    - imul
    - or
    - and
    - shl
    - inc
    - dec
    - not
    - sal
  - 仅设置条件码的指令
    - cmp
    - test
- 条件转跳指令
  - 根据条件码ZF和SF实现转跳
- if-else语句的通用形式
  - 结构
    - if(test_expr)
      - then_statement
    - else
      - else_statement
  - test_expr特性
    - 整数表达式
    - 0(假)或非0(真)
  - 执行特点
    - 仅执行一个分支
- goto语句形式
  - 翻译示例
    - t=test_expr;
    - if(!t) goto false;
    - then_statement
    - goto done;
    - false:
      - else_statement
    - done:
- C语言函数示例
  - 函数定义
    - int get_cont(int *p1,int *p2)
  - 实现逻辑
    - if(p1>p2) return *p2;
    - else return *p1;
  - 参数存储
    - p1: R[ebp]+8
    - p2: R[ebp]+12
    - EBP指向当前栈帧底部
  - 返回结果存储
    - EAX
- 汇编实现要点
  - 32位机指针参数长度
    - dword ptr
  - 比较指令要求
    - cmp的两个操作数都应来自寄存器
  - 执行流程
    - 从栈中取参数到通用寄存器
    - 执行比较指令设置条件码
    - 根据条件码组合选择执行路径
    - 使用条件转移指令
### 4.3.3    循环语句的机器级表示 
- 常见循环结构
  - while
  - for
  - do-while
- 实现方式
  - 汇编中用条件测试和转跳组合实现循环
  - 大多数编译器转换为do-while形式
  - 使用条件转移指令判断循环结束
- do-while循环
  - 通用形式
    - do body_statement while(test_expr)
  - 机器级表示
    - loop: body_statement if(t) goto loop
- while循环
  - 通用形式
    - while(test_expr) body_statement
  - 机器级表示
    - t=test_expr; if(!t) goto done; do body_statement while(test_expr); done:
  - goto语句表示
    - t=test-expr; goto done; loop: body_statement if(t) goto loop; done:
- for循环
  - 通用形式
    - for(init_expr;test_expr;update_expr) body_statement
  - 等效while循环
    - init_expr; while(test_expr){ body_statement update_expr; }
  - goto语句表示
    - init_expr; t=test_expr; if(!t) goto done; loop: body_statement update_expr; if(t) goto loop; done:
### 4.3.4    过程调用的机器级表示 
- 过程调用步骤
  - 1) P将入口参数放到Q能访问的地方
  - 2) P将返回地址存到特定地方，控制转移到Q
  - 3) Q保存P的现场，分配局部变量空间
  - 4) 执行过程Q
  - 5) Q恢复P的现场，返回结果，释放空间
  - 6) Q取出返回地址，控制转移到P
- 指令实现
  - call指令实现步骤2
  - ret指令实现步骤6
- 寄存器规范
  - 调用者保存寄存器
    - EAX
    - ECX
    - EDX
  - 被调用者保存寄存器
    - EBX
    - ESI
    - EDI
- 栈帧结构
  - 每个过程有自己的栈区（栈帧）
  - EBP指示栈帧起始位置
  - ESP指示栈顶
  - 栈从高地址向低地址增长
- 示例程序分析
  - caller函数
    - 局部变量
      - temp1=125
      - temp2=80
      - sum
    - 调用add函数
      - 参数入栈顺序：从右向左
      - 返回值保存在EAX
  - add函数
    - 准备阶段
      - push ebp
      - mov ebp,esp
    - 过程体
      - lea指令实现加法
    - 结束阶段
      - pop ebp
      - ret
- leave指令功能
  - mov esp,ebp
  - pop ebp
## 4.4  CISC 和 RISC 的基本概念 
### 4.4.1    复杂指令系统计算机(CISC)  
- CISC的主要特点
  - 指令系统复杂庞大
    - 指令数目一般为200条以上
  - 指令的长度不固定
    - 指令格式多
    - 寻址方式多
  - 可以访存的指令不受限制
  - 各种指令使用频度相差很大
  - 各种指令执行时间相差很大
    - 大多数指令需多个时钟周期才能完成
  - 控制器大多数采用微程序控制
  - 难以用优化编译生成高效的目标代码程序
- CISC的问题
  - 研制周期长
  - 指令使用频率悬殊
    - 20%的简单指令占整个程序的80%
    - 80%的复杂指令占整个程序的20%
- CISC的发展结果
  - 用20%的常用简单指令重组实现80%的复杂指令功能
  - RISC随之诞生
### 4.4.2    精简指令系统计算机(RISC)  
- 中心思想
  - 指令系统简化
  - 尽量使用寄存器-寄存器操作指令
  - 指令格式力求一致
- 主要特点
  - 1) 选取使用频率高的简单指令
    - 复杂指令由简单指令组合实现
  - 2) 指令长度固定
    - 指令格式种类少
    - 寻址方式种类少
  - 3) 访存指令限制
    - 只有LOAD/STORE指令访存
    - 其余指令在寄存器间操作
  - 4) 通用寄存器数量多
  - 5) 指令流水线技术
    - 大部分指令单周期完成
  - 6) 控制方式
    - 以硬布线控制为主
    - 少用微程序控制
  - 7) 重视编译优化
    - 减少程序执行时间
- 兼容性比较
  - CISC
    - 大多能实现软件兼容
  - RISC
    - 指令系统简化
    - 指令条数少
    - 格式不同于老机器
    - 大多数不能与老机器兼容
- 发展趋势
  - RISC优势
    - 更强的实用性
      - 未来处理器发展方向
  - 现状
    - Intel主导市场
    - 早期软件基于CISC设计
      - 单纯RISC无法兼容
    - 现代CISC融合RISC技术
      - 性能差距缩小
      - CISC提供更多功能
        - 程序设计需要
### 4.4.3    CISC 和 RISC 的比较 
- RISC的优点
  - 更能充分利用VLSI芯片面积
    - CISC采用微程序控制
      - 控制存储器占CPU芯片面积50%以上
    - RISC采用组合逻辑控制
      - 硬布线逻辑只占CPU芯片面积10%左右
  - 更能提高运算速度
    - 指令数、寻址方式和指令格式种类少
    - 设有多个通用寄存器
    - 采用流水线技术
    - 大多数指令在一个时钟周期内完成
  - 便于设计，可降低成本，提高可靠性
    - 指令系统简单，机器设计周期短
    - 逻辑简单，出错概率低，有错易发现
  - 有利于编译程序代码优化
    - 指令类型少，寻址方式少
    - 编译程序容易选择更有效的指令和寻址方式
    - 可适当调整指令顺序使代码执行更高效
- CISC和RISC对比表
  - 指令系统
    - CISC
      - 指令数量多（100~250条）
      - 指令格式复杂（多种长度）
      - 寻址方式多（5~20种）
    - RISC
      - 指令数量少（<100条）
      - 指令格式固定（等长）
      - 寻址方式少（1~5种）
  - 执行速度
    - CISC
      - 大多数指令需要多个时钟周期
      - 难以实现流水线并行
    - RISC
      - 大多数指令单周期完成
      - 适合流水线并行处理
  - 硬件复杂度
    - CISC
      - 微程序控制器占较大面积
      - 硬件逻辑复杂
    - RISC
      - 硬布线控制器为主
      - 硬件逻辑简单
  - 寄存器使用
    - CISC
      - 专用寄存器为主
      - 寄存器数量较少
    - RISC
      - 通用寄存器为主
