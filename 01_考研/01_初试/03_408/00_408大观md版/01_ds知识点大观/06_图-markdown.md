# 第六章 图
## 6.1   图的基本概念
### 6.1.1   图的定义
- 图G由顶点集V和边集E组成，记为G=(V,E)
  - V(G): 图G中顶点的有限非空集
  - E(G): 图G中顶点之间的关系(边)集合
- 线性表可以是空表，树可以是空树，但图不可以是空图
  - 顶点集V一定非空
  - 边集E可以为空

- 基本概念及术语
  - 有向图
    - E是有向边(弧)的有限集合
    - 弧是顶点的有序对，记为<v,w>
      - v称为弧尾
      - w称为弧头
      - <v,w>称为从v到w的弧
  
  - 无向图
    - E是无向边的有限集合
    - 边是顶点的无序对，记为(v,w)或(w,v)
  
  - 简单图、多重图
    - 简单图
      - 不存在重复边
      - 不存在顶点到自身的边
    - 多重图
      - 两个顶点之间的边数大于1条
      - 允许顶点通过一条边和自身关联
  
  - 顶点的度、入度和出度
    - 无向图
      - 顶点v的度TD(v): 依附于顶点v的边的条数
      - 全部顶点的度之和等于边数的2倍
    - 有向图
      - 入度ID(v): 以顶点v为终点的有向边的数目
      - 出度OD(v): 以顶点v为起点的有向边的数目
      - 顶点v的度TD(v)=ID(v)+OD(v)
      - 全部顶点的入度之和与出度之和相等，并且等于边数
  
  - 路径、路径长度和回路
    - 路径: 顶点序列vp,v₁,V₂,...,vm,vq
    - 路径长度: 路径上的边的数目
    - 回路或环: 第一个顶点和最后一个顶点相同的路径
    - 若一个图有n个顶点，且有大于n-1条边，则此图一定有环
  
  - 简单路径、简单回路
    - 简单路径: 顶点不重复出现的路径
    - 简单回路: 除第一个和最后一个顶点外，其余顶点不重复出现的回路
  
  - 距离
    - 从顶点u到顶点v的最短路径的长度
    - 若不存在路径，则记距离为无穷(∞)
  
  - 子图
    - G'=(V',E')是G=(V,E)的子图
      - V'是V的子集
      - E'是E的子集
    - 生成子图: 满足V(G')=V(G)的子图G'
  
  - 连通、连通图和连通分量
    - 无向图
      - 连通: 从顶点v到顶点w有路径存在
      - 连通图: 任意两个顶点都是连通的
      - 非连通图: 否则
      - 连通分量: 极大连通子图
      - 若边数小于n-1，则必是非连通图
  
  - 强连通图、强连通分量
    - 有向图
      - 强连通: 从v到w和从w到v之间都有路径
      - 强连通图: 任意一对顶点都是强连通的
      - 强连通分量: 极大强连通子图
  
  - 生成树、生成森林
    - 生成树: 包含图中全部顶点的极小连通子图
      - 含有n-1条边
    - 生成森林: 非连通图中连通分量的生成树
  
  - 边的权、网和带权路径长度
    - 权值: 边上具有某种含义的数值
    - 带权图(网): 边上带有权值的图
    - 带权路径长度: 路径上所有边的权值之和
  
  - 完全图(简单完全图)
    - 无向图
      - 边数n(n-1)/2
      - 任意两个顶点之间都存在边
    - 有向图
      - 边数n(n-1)
      - 任意两个顶点之间都存在方向相反的两条弧
  
  - 稠密图、稀疏图
    - 稀疏图: 边数很少的图
    - 稠密图: 边数很多的图
    - 当|E|<|V|log₂|V|时，可视为稀疏图
  
  - 有向树
    - 一个顶点的入度为0
    - 其余顶点的入度均为1
## 6.2   图的存储及基本操作
### 6.2.1   邻接矩阵法
- 定义
  - 用一个一维数组存储图中顶点的信息
  - 用一个二维数组存储图中边的信息（邻接关系）
  - 存储邻接关系的二维数组称为邻接矩阵
- 顶点数为n的图G=(V,E)的邻接矩阵
  - 是n×n的矩阵
  - 顶点编号为v₁,v₂,...,vₙ
- 带权图的邻接矩阵
  - 有边相连：存储对应权值
  - 无边相连：通常用0或∞表示
- 存储结构定义
  - #define MaxVertexNum 100 // 定义图的最大顶点数为 100  
  - typedef char VertexType // 定义顶点数据类型为 char（例如用字符表示顶点）  
  - typedef int EdgeType // 定义边的权值类型为 int（若为无权图，也可用于标记是否相连）  
  - typedef struct { } MGraph; // 结构体类型名为 MGraph
  - VertexType vex[MaxVertexNum]; // 存储顶点信息的数组  
  - EdgeType edge[MaxVertexNum][MaxVertexNum]; // 邻接矩阵，表示边的关系  
  - int vexnum, arcnum; // 当前图中的顶点数和边数  
- 特点
  - 无向图的邻接矩阵
    - 是对称矩阵（且唯一）
    - 实际只需存储上/下三角矩阵
  - 无向图顶点度的计算
    - 第i行/列非零元素个数=顶点i的度TD(vᵢ)
  - 有向图顶点度的计算
    - 第i行非零元素个数=出度OD(vᵢ)
    - 第i列非零元素个数=入度ID(vᵢ)
  - 优点
    - 容易判断任意两顶点是否有边相连
  - 缺点
    - 统计边数需要遍历整个矩阵
  - 适用场景
    - 稠密图（边数较多的图）
  - 邻接矩阵的幂
    - Aⁿ[i][j]表示顶点i到j长度为n的路径数目
### 6.2.2   邻接表法
- 定义
  - 对稀疏图更节省存储空间
  - 结合顺序存储和链式存储方法
  - 对每个顶点建立单链表（边表/出边表）
- 存储结构
  - 顶点表（顺序存储）
    - 数据域（data）
    - 边表头指针（firstarc）
  - 边表结点（链式存储）
    - 邻接点域（adjvex）
    - 指针域（nextarc）
- 代码定义
  - ArcNode结构体
    - adjvex（弧指向的顶点位置）
    - nextarc（指向下一条弧的指针）
  - VNode结构体
    - data（顶点信息）
    - firstarc（指向第一条依附的弧）
  - ALGraph结构体
    - vertices（邻接表数组）
    - vexnum（顶点数）
    - arcnum（弧数）
- 特点
  - 空间复杂度
    - 无向图：O(|V|+2|E|)
    - 有向图：O(|V|+|E|)
  - 适用性
    - 对稀疏图节省存储空间
  - 操作效率
    - 找邻边容易（直接读邻接表）
    - 判断两顶点间是否存在边效率较低
  - 度计算
    - 无向图：边表结点个数即度数
    - 有向图
      - 出度：边表结点个数
      - 入度：需遍历全部邻接表统计
  - 表示不唯一
    - 边表结点链接次序任意
### 6.2.3   十字链表
- 定义
  - 有向图的一种链式存储结构
- 结点类型
  - 弧结点
    - 结构
      - tailvex域：存放弧尾顶点编号
      - headvex域：存放弧头顶点编号
      - hlink域：指向弧头相同的下一条弧
      - tlink域：指向弧尾相同的下一条弧
      - info域：存放该弧的相关信息
  - 顶点结点
    - 结构
      - data域：存放顶点数据信息（如顶点名称）
      - firstin域：指向以该顶点为弧头的第一条弧
      - firstout域：指向以该顶点为弧尾的第一条弧
- 存储特点
  - 弧头相同的弧在同一个链表上
  - 弧尾相同的弧在同一个链表上
  - 顶点结点之间是顺序存储的
- 操作特性
  - 容易找到以Vi为尾的弧
  - 容易找到以Vi为头的弧
  - 容易求得顶点的出度和入度
- 唯一性
  - 图的十字链表表示不唯一
  - 一个十字链表表示唯一确定一个图
### 6.2.4   邻接多重表
- 定义
  - 无向图的一种链式存储结构
- 邻接表的缺点
  - 求两个顶点之间是否存在边或执行删除边等操作效率低
    - 需要在两个顶点的边表中遍历
- 结构特点（类似十字链表）
  - 每条边用一个结点表示
    - 结点结构
      - ivex域：存放该边依附的第一个顶点编号
      - jvex域：存放该边依附的第二个顶点编号
      - ilink域：指向依附于顶点ivex的下一条边
      - jlink域：指向依附于顶点jvex的下一条边
      - info域：存放该边的相关信息
  - 每个顶点用一个结点表示
    - 结点结构
      - data域：存放该顶点的相关信息
      - firstedge域：指向依附于该顶点的第一条边
- 存储特点
  - 所有依附于同一顶点的边串联在同一链表中
  - 每个边结点同时链接在两个链表中（因为每条边依附于两个顶点）
- 与邻接表的区别
  - 邻接表：同一条边用两个结点表示
  - 邻接多重表：同一条边用一个结点表示
- 操作实现
  - 各种基本操作的实现和邻接表类似
### 6.2.5   图的基本操作
- 特点
  - 独立于图的存储结构
  - 不同存储方式影响算法性能
- 基本操作列表
  - Adjacent(G,x,y)
    - 功能：判断图G是否存在边<x,y>或(x,y)
  - Neighbors(G,x)
    - 功能：列出图G中与结点x邻接的边
  - InsertVertex(G,x)
    - 功能：在图G中插入顶点x
  - DeleteVertex(G,x)
    - 功能：从图G中删除顶点x
  - AddEdge(G,x,y)
    - 功能：向图G中添加不存在的边
    - 适用：无向边(x,y)或有向边<x,y>
  - RemoveEdge(G,x,y)
    - 功能：从图G中删除存在的边
    - 适用：无向边(x,y)或有向边<x,y>
  - FirstNeighbor(G,x)
    - 功能：求顶点x的第一个邻接点
    - 返回值：顶点号/-1
  - NextNeighbor(G,x,y)
    - 功能：返回x的下一个邻接点（除y外）
    - 返回值：顶点号/-1
  - Get_edge_value(G,x,y)
    - 功能：获取边的权值
  - Set_edge_value(G,x,y,v)
    - 功能：设置边的权值为v
- 图的遍历算法
  - 特点：访问每个顶点且仅访问一次
  - 类型
    - 深度优先遍历
    - 广度优先遍历
## 6.3   图的遍历
### 6.3.1   广度优先搜索
- 基本思想
  - 类似于树的层序遍历
  - 从起始顶点v出发，依次访问v的未访问邻接顶点w1,w2,...,wi
  - 再依次访问w1,w2,...,wi的所有未访问邻接顶点
  - 重复上述过程，直到所有顶点被访问
  - 若存在未访问顶点，另选一个未访问顶点作为起始点继续
- 特点
  - 分层查找过程，由近及远访问顶点
  - 非递归算法，需要借助辅助队列
- 应用
  - Dijkstra单源最短路径算法
  - Prim最小生成树算法
- 算法实现
  - 伪代码
    - 初始化访问标记数组visited[]
    - 初始化队列Q
    - 对每个未访问顶点调用BFS()
  - 邻接表实现
    - 访问初始顶点i并标记
    - 顶点i入队
    - 循环处理队列直到为空
      - 队首顶点v出队
      - 访问v的所有未访问邻接点w
        - 访问w并标记
        - w入队
  - 邻接矩阵实现
    - 类似邻接表实现
    - 通过二维数组edge[v][w]判断邻接关系
- 性能分析
  - 空间复杂度
    - 辅助队列O(V)
  - 时间复杂度
    - 邻接表存储：O(V+E)
    - 邻接矩阵存储：O(V²)
- 应用：单源最短路径问题
  - 非带权图的最短路径定义
  - BFS求解算法
    - 初始化路径长度数组d[]
    - 从顶点u开始BFS
    - 更新邻接点w的路径长度d[w]=d[u]+1
- 广度优先生成树
  - 遍历过程中得到的生成树
  - 邻接矩阵存储的生成树唯一
  - 邻接表存储的生成树不唯一
### 6.3.2  深度优先搜索
- 深度优先搜索(DFS)
  - 基本概念
    - 类似于树的先序遍历
    - 策略：尽可能"深"地搜索一个图
  - 基本思想
    - 从起始顶点v开始访问
    - 访问v的未访问邻接顶点w1
    - 继续深入访问w1的未访问邻接顶点w2
    - 无法继续时回退到最近访问顶点
    - 检查是否有未访问邻接顶点
    - 重复直到所有顶点被访问
  - 算法实现
    - 递归形式
      - 简洁
    - 伪代码
      - 访问标记数组visited[MAX_VERTEX_NUM]
      - DFSTraverse函数
        - 初始化visited数组
        - 对未访问顶点调用DFS
      - DFS函数
        - 访问顶点i
        - 标记i为已访问
        - 检查i的所有邻接点
          - 对未访问邻接点递归调用DFS
  - 具体实现
    - 邻接表实现
      - 使用指针遍历邻接表
      - 时间复杂度：O(|V|+|E|)
    - 邻接矩阵实现
      - 遍历矩阵行/列
      - 时间复杂度：O(|V|²)
  - 性能分析
    - 空间复杂度
      - O(|V|)（递归栈）
    - 时间复杂度
      - 邻接矩阵：O(|V|²)
      - 邻接表：O(|V|+|E|)
  - 生成树和森林
    - 深度优先生成树
      - 连通图产生生成树
    - 深度优先生成森林
      - 非连通图产生生成森林
    - 基于邻接表的生成树不唯一
### 6.3.3  图的遍历与图的连通性
- 图的遍历算法用于判断图的连通性
  - 无向图
    - 连通图
      - 从任意结点出发，一次遍历可访问所有顶点
    - 非连通图
      - 一次遍历只能访问当前连通分量的顶点
      - 无法访问其他连通分量的顶点
  - 有向图
    - 若初始顶点到每个顶点都有路径
      - 可访问所有顶点
    - 否则
      - 不能访问所有顶点
- 遍历算法的实现
  - BFSTraverse()或DFSTraverse()中添加第二个for循环
    - 目的：防止一次无法遍历所有顶点
    - 机制：重新选取初始点继续遍历
- 连通分量判断
  - 无向图
    - 调用BFS(G,i)或DFS(G,i)的次数等于连通分量数
  - 有向图
    - 连通子图分类
      - 强连通分量
      - 非强连通分量
    - 非强连通分量特性
      - 一次调用BFS(G,i)或DFS(G,i)不一定能访问所有顶点
## 6.4   图的应用
### 6.4.1   最小生成树
- 定义
	  - 连通图的生成树包含所有顶点，且边数尽可能少
	  - 砍去一条边会变成非连通图
	  - 增加一条边会形成回路
- 最小生成树(MST)
	  - 带权连通无向图中权值之和最小的生成树
- 性质
	  - 存在权值相同边时，MST可能不唯一
	  - 边权值互不相等时，MST唯一
	  - 边数=顶点数-1时，图本身就是MST
	  - 权值之和唯一且最小
	  - 边数=顶点数-1
- 构造算法通用原理
	  - 假设G=(V,E)是带权连通无向图
	  - U是V的非空子集
	  - 若(u,v)是U与V-U间最小权值边，则必存在包含(u,v)的MST
- 通用算法
  - GENERIC_MST(G)
    - T=NULL
    - while T未形成生成树
      - 找到最小代价边(u,v)且加入T不产生回路
      - T=T∪(u,v)
- Prim算法
  - 执行过程
    - 从任意顶点开始
    - 每次选择与当前树距离最近的顶点加入
    - 直至所有顶点都并入
  - 步骤
    - 初始化：U={u0}, Er=∅
    - 循环直至U=V
      - 选择U与V-U间最小权值边(u,v)
      - U=U∪{v}, Er=Er∪{(u,v)}
  - 特点
    - 时间复杂度O(|V|²)
    - 适用于边稠密图
- Kruskal算法
  - 执行过程
    - 初始为n个孤立顶点
    - 按权值递增顺序选择边
    - 若边连接不同连通分量则加入
    - 直至所有顶点连通
  - 步骤
    - 初始化：U=V, Er=∅
    - 循环直至T成为树
      - 选择权值最小边
      - 若加入后不构成回路则加入Er
  - 特点
    - 时间复杂度O(|E|log|E|)
    - 适用于边稀疏图
    - 使用并查集判断连通分量
### 6.4.2   最短路径
- 定义
  - 无权图的最短路径：广度优先搜索
  - 带权图的最短路径：带权路径长度最短的路径
- 分类
  - 单源最短路径
    - Dijkstra算法
  - 每对顶点间的最短路径
    - Floyd算法
- Dijkstra算法
  - 基本思想
    - 集合S记录已求得最短路径的顶点
    - 初始时源点v0放入S
    - 每次并入新顶点vi时修改v0到V-S中顶点的最短路径长度
  - 辅助数组
    - final[]：标记顶点是否已找到最短路径
    - dist[]：记录v0到其他顶点的当前最短路径长度
    - path[]：记录最短路径的前驱结点
  - 算法步骤
    - 初始化
    - 从V-S中选出dist最小的顶点vj并入S
    - 修改v0到V-S中顶点的最短路径长度
    - 重复n-1次
  - 时间复杂度
    - 邻接矩阵：O(V²)
    - 邻接表：O(V²)
  - 局限性
    - 不适用于带负权值的边
  - 与Prim算法的比较
    - 目的不同
    - 算法思路不同
    - 适用图不同
- Floyd算法
  - 基本思想
    - 递推产生n阶方阵序列A(-1),A(0),...,A(n-1)
    - A(k)[i][j]表示从vi到vj中间顶点序号不大于k的最短路径长度
  - 算法描述
    - 初始化A(-1)[i][j]=arcs[i][j]
    - 迭代更新A(k)[i][j]
  - 时间复杂度：O(V³)
  - 特点
    - 允许带负权值的边
    - 不允许总权值为负的回路
    - 适用于带权无向图
- 算法总结
  - BFS算法
  - Dijkstra算法
  - Floyd算法
### 6.4.3   有向无环图描述表达式
- 有向无环图定义
  - 若一个有向图中不存在环，则称为有向无环图
  - 简称 DAG 图
- 应用场景
  - 描述含有公共子式的表达式的有效工具
  - 举例表达式：(a+b)*(b*(c+d)+(c+d)*e)*((c+d)*e)
- 与传统表示法的比较
  - 二叉树表示
    - 相同子表达式会重复出现（如(c+d)和(c+d)*e）
  - 有向无环图表示
    - 可以实现对相同子式的共享
    - 节省存储空间


### 6.4.4   拓扑排序
- AOV 网
  - 定义：有向无环图表示工程，顶点表示活动
  - 有向边<V,V>表示活动V必须先于活动V进行
  - 性质
    - 前驱和后继关系具有传递性
    - 任何活动不能以自己作为前驱或后继
- 拓扑排序
  - 定义
    - 有向无环图顶点组成的序列
    - 条件
      - 每个顶点出现且只出现一次
      - 若顶点A排在顶点B前面，则不存在从B到A的路径
  - 性质
    - 每个AOV网都有一个或多个拓扑排序序列
  - 算法步骤
    - 从AOV网中选择入度为0的顶点并输出
    - 删除该顶点和所有以它为起点的有向边
    - 重复直到AOV网为空或不存在无前驱顶点
  - 逆拓扑排序
    - 步骤
      - 选择出度为0的顶点并输出
      - 删除该顶点和所有以它为终点的有向边
      - 重复直到AOV网为空
  - 注意事项
    - 入度为零的顶点代表可以开始或继续的活动
    - 拓扑排序结果可能不唯一
      - 唯一性判断条件：每次输出时入度为0的顶点是否唯一
    - AOV网顶点地位平等，可重新编号
      - 新邻接矩阵可以是三角矩阵
      - 一般图的邻接矩阵是三角矩阵则存在拓扑序列，反之不一定
### 6.4.5   关键路径
- AOE网定义
  - 带权有向图
  - 顶点表示事件
  - 有向边表示活动
  - 边权值表示活动开销
- AOE网与AOV网区别
  - AOE网边有权值
  - AOV网边无权值
- AOE网性质
  - 性质1：顶点事件发生后，出发活动才能开始
  - 性质2：进入顶点的活动都结束后，顶点事件才能发生
  - 仅一个入度为0的顶点（源点）
  - 仅一个出度为0的顶点（汇点）
- 关键路径定义
  - 从源点到汇点的最长路径
  - 关键路径上的活动称为关键活动
  - 关键路径长度=工程最短完成时间
- 关键路径相关参量
  - 事件v的最早发生时间ve(k)
    - 定义：源点到顶点vk的最长路径长度
    - 递推公式
      - ve(源点)=0
      - ve(k)=Max{ve(j)+Weight(vj,vk)}
  - 事件v的最迟发生时间vl(k)
    - 定义：不推迟整个工程的前提下，事件最迟必须发生的时间
    - 递推公式
      - vl(汇点)=ve(汇点)
      - vl(k)=Min{vl(j)-Weight(vk,vj)}
  - 活动a的最早开始时间e(i)
    - 定义：活动弧起点事件的最早发生时间
    - 公式：e(i)=ve(k)
  - 活动a的最迟开始时间l(i)
    - 定义：活动弧终点事件的最迟发生时间减去活动时间
    - 公式：l(i)=vl(j)-Weight(vk,vj)
  - 活动时间余量d(i)
    - 定义：d(i)=l(i)-e(i)
    - 关键活动条件：d(i)=0
- 求关键路径算法步骤
  - 拓扑有序求ve()
  - 逆拓扑有序求vl()
  - 根据ve()求所有弧的e()
  - 根据vl()求所有弧的l()
  - 求所有活动的d()，d(i)=0的活动构成关键路径
- 关键路径注意事项
  - 关键路径不唯一
  - 加快关键活动可缩短工期
    - 但不能任意缩短
  - 多条关键路径时，需加快所有关键路径共有的关键活动才能缩短工期
