# 第 1 章 计算机系统概述
## 1.1   操作系统的基本概念
### 1.1.1   操作系统的概念 
- 计算机系统分层
  - 硬件
    - 中央处理器
    - 内存
    - 输入/输出设备
  - 操作系统
  - 应用程序
    - 字处理程序
    - 电子制表软件
    - 编译器
    - 网络浏览器
  - 用户
- 操作系统功能
  - 控制和管理计算机系统硬件与软件资源
  - 合理组织、调度计算机工作与资源分配
  - 为用户和其他软件提供方便接口与环境
- 操作系统定位
  - 计算机系统中最基本的系统软件
  - 软件核心
  - 计算机硬件与用户之间的中介
### 1.1.2   操作系统的特征
- 功能
  - 处理机管理
  - 存储器管理
  - 设备管理
  - 文件管理
  - 用户接口
- 目标
  - 提供良好的运行环境
  - 方便用户使用
  - 扩充机器功能
  - 提高资源利用率
- 操作系统作为计算机系统资源的管理者
  - 处理机管理
    - 进程为基本单位
    - 并发管理
    - 主要功能
      - 进程控制
      - 进程同步
      - 进程通信
      - 死锁处理
      - 处理机调度
  - 存储器管理
    - 主要功能
      - 内存分配与回收
      - 地址映射
      - 内存保护与共享
      - 内存扩充
  - 文件管理
    - 文件系统
    - 主要功能
      - 文件存储空间管理
      - 目录管理
      - 文件读写管理
      - 文件保护
  - 设备管理
    - 主要功能
      - 缓冲管理
      - 设备分配
      - 设备处理
      - 虚拟设备
- 操作系统作为用户与计算机硬件系统之间的接口
  - 命令接口
    - 联机命令接口（交互式）
      - 分时/实时系统
      - 键盘操作命令
    - 脱机命令接口（批处理）
      - 批处理系统
      - 作业控制命令
  - 程序接口
    - 系统调用（广义指令）
    - 图形用户界面（GUI）
      - 调用程序接口实现
- 操作系统实现了对计算机资源的扩充
  - 裸机
  - 扩充机器/虚拟机
    - 操作系统覆盖
    - 功能更强
    - 使用更方便
### 1.1.3    操作系统的目标和功能
- 并发 (Concurrence)
  - 定义：两个或多个事件在同一时间间隔内发生
  - 多道程序环境下的实现方式
    - 利用I/O操作暂停时的CPU空档时间
    - 多道程序交替运行
  - 并发与并行的区别
    - 并发：同一时间间隔
    - 并行：同一时刻
    - 示例说明
      - 并发示例：9:00-10:00交替吃面包和写字
      - 并行示例：同时用右手写字和左手吃面包
  - 进程引入目的：实现程序并发执行
- 共享 (Sharing)
  - 定义：系统中的资源可供多个并发进程共同使用
  - 共享方式
    - 互斥共享
      - 特点：一段时间内只允许一个进程访问
      - 示例：打印机、磁带机
      - 临界资源概念
    - 同时访问
      - 特点：宏观"同时"，微观分时
      - 示例：磁盘设备、重入代码编写的文件
  - 并发与共享的关系
    - 互为存在条件
    - 资源共享以并发为前提
    - 资源共享管理影响并发执行
- 虚拟 (Virtual)
  - 定义：将物理实体变为逻辑对应物
  - 虚拟技术类型
    - 时分复用技术
      - 示例：虚拟处理器
    - 空分复用技术
      - 示例：虚拟存储器
  - 具体应用
    - 虚拟处理器：通过多道程序设计实现
    - 虚拟存储器：逻辑扩充存储容量
    - 虚拟设备：将物理I/O设备虚拟为多个逻辑设备
- 异步 (Asynchronism)
  - 定义：进程以不可预知的速度执行
  - 产生原因：多道程序环境下资源有限
  - 影响
    - 可能导致与时间有关的错误
  - 操作系统要求
    - 相同环境下多次运行结果一致
## 1.2    操作系统发展历程
### 1.2.1    手工操作阶段(此阶段无操作系统)
- 特点
  - 用户在计算机上算题的所有工作都要人工干预
    - 程序的装入
    - 运行
    - 结果的输出
  - 随着计算机硬件的发展，人机矛盾(速度和资源利用)越来越大
- 缺点
  - 用户独占全机
    - 不会出现因资源已被其他用户占用而等待的现象
    - 资源利用率低
  - CPU等待手工操作
    - CPU的利用不充分
- 解决办法
  - 用高速的机器代替相对较慢的手工操作来对作业进行控制
### 1.2.2    批处理阶段(操作系统开始出现)
- 出现原因
  - 解决人机矛盾
  - 解决CPU和I/O设备速度不匹配
- 发展阶段
  - 单道批处理系统
  - 多道批处理系统(多道程序设计技术出现后)
- 批处理系统特点
  - 单道批处理系统
    - 实现方式
      - 作业脱机输入磁带
      - 监督程序控制连续处理
    - 主要特征
      - 自动性: 作业自动逐个运行
      - 顺序性: 作业按顺序进入内存
      - 单道性: 内存仅一道程序运行
    - 问题
      - CPU等待低速I/O
  - 多道批处理系统
    - 特点
      - 多道程序设计特点
        - 多道: 内存同时存放多道程序
        - 宏观并行: 多道程序同时运行
        - 微观串行: 轮流占有CPU
      - 实现需解决问题
        - 处理器分配
        - 内存分配
        - I/O设备分配
        - 程序和数据组织存储
    - 系统特点
      - 优点
        - 资源利用率高
        - 系统吞吐量大
      - 缺点
        - 用户响应时间长
        - 缺乏人机交互能力

### 1.2.3    分时操作系统 
- 分时技术
  - 将处理器运行时间分成很短的时间片
  - 按时间片轮流分配给各联机作业使用
  - 作业在时间片内未完成则暂停运行
  - 等待下一轮继续运行
- 定义
  - 多个用户通过终端同时共享一台主机
  - 用户可以同时与主机交互操作而互不干扰
- 关键问题
  - 及时接收和处理用户命令
  - 将结果返回用户
- 与多道批处理系统的区别
  - 分时系统：实现人机交互
  - 多道批处理：实现作业自动控制
- 主要特征
  - 同时性（多路性）
    - 允许多个终端用户同时使用计算机
  - 交互性
    - 用户通过终端直接控制程序运行
  - 独立性
    - 多个用户彼此独立操作
    - 单个用户感觉独占计算机
  - 及时性
    - 用户请求能在很短时间内获得响应
- 局限性
  - 无法满足对外部信息在规定时间内处理的需求
  - 导致实时操作系统的出现
### 1.2.4    实时操作系统 
- 定义
  - 能在时间限制内完成紧急任务而不需要时间片排队
- 分类
  - 硬实时系统
    - 必须在规定时刻/时间范围内发生
    - 例子：飞行器飞行自动控制系统
    - 特点：必须绝对保证特定动作在规定时间内完成
  - 软实时系统
    - 可偶尔违反时间规定且不会造成永久损害
    - 例子：飞机订票系统、银行管理系统
- 工作原理
  - 接收到外部信号后及时处理
  - 在严格时限内处理完接收的事件
- 主要特点
  - 及时性
  - 可靠性
### 1.2.5    网络操作系统和分布式计算机系统 
- 网络操作系统
  - 定义：伴随计算机网络发展而诞生
  - 功能
    - 将各台计算机有机结合
    - 实现计算机间通信和数据传送
    - 实现网络中资源共享
- 分布式计算机系统
  - 定义：由多台计算机组成的系统
  - 条件
    - 任意两台计算机通过通信交换信息
    - 每台计算机地位平等（无主从关系）
    - 每台计算机资源为所有用户共享
    - 任意计算机可构成子系统并可重构
    - 工作可分布在多台计算机上并行协同完成
  - 分布式操作系统
    - 定义：用于管理分布式计算机系统的操作系统
    - 主要特点
      - 分布性
      - 并行性
    - 与网络操作系统的本质区别
      - 分布式操作系统中计算机协同完成同一任务
### 1.2.6   个人计算机操作系统 
- 定义
  - 目前使用最广泛的操作系统
- 应用领域
  - 文字处理
  - 电子表格
  - 游戏
- 常见系统
  - Windows
  - Linux
  - MacOS
- 其他操作系统类型
  - 嵌入式操作系统
  - 服务器操作系统
  - 智能手机操作系统

## 1.3    操作系统的运行环境
### 1.3.1    处理器运行模式 
- CPU执行程序类型
  - 操作系统内核程序（管理程序）
    - 执行特权指令
  - 用户自编程序（被管理程序）
    - 不能执行特权指令
- 指令分类
  - 特权指令
    - 不允许用户直接使用
    - 示例：I/O指令、关中断指令、内存清零指令等
  - 非特权指令
    - 允许用户直接使用
    - 只能访问用户地址空间
- CPU运行状态
  - 用户态（目态）
    - 只能执行非特权指令
  - 内核态（管态/核心态）
    - 可以执行特权指令
    - 包含切换用户态的指令
- 操作系统内核
  - 时钟管理
    - 功能
      - 计时
      - 进程切换
  - 中断机制
    - 作用
      - 提高CPU利用率
      - 操作系统基础
    - 内核功能
      - 保护和恢复中断现场
      - 转移控制权
  - 原语
    - 特点
      - 接近硬件
      - 原子性
      - 运行时间短且调用频繁
    - 实现方法
      - 关中断
      - 完成操作后开中断
  - 系统控制的数据结构及处理
    - 数据结构示例
      - 作业控制块
      - 进程控制块(PCB)
      - 设备控制块
    - 基本操作
      - 进程管理
        - 进程状态管理
        - 进程调度和分派
      - 存储器管理
        - 空间分配和回收
        - 内存信息保护
      - 设备管理
        - 缓冲区管理
        - 设备分配和回收

### 1.3.2    中断和异常的概念 
- 内中断和外中断的联系与区别  
  - 中断(Interruption)  
    - 外中断  
    - 用于信息输入/输出  
    - 示例  
      - I/O结束中断  
      - 时钟中断  

  - 异常(Exception)  
    - 内中断  
    - 示例  
      - 非法操作码  
      - 地址越界  
      - 运算溢出  
      - 缺页  
      - 陷入指令  
    - 不能被屏蔽  

- 中断和异常的分类  
  - 外中断分类  
    - 可屏蔽中断(INTR)  
    - 不可屏蔽中断(NMI)  
  - 异常分类  
    - 故障(Fault)  
      - 示例  
        - 非法操作码  
        - 缺页故障  
        - 除数为0  
        - 运算溢出  
    - 自陷(Trap)  
      - 示例  
        - 条件陷阱指令  
        - 系统调用指令  
    - 终止(Abort)  
      - 示例  
        - 控制器出错  
        - 存储器校验错  

- 中断和异常的处理过程  
  - 处理流程  
    - 检测异常/中断  
    - 转中断/异常处理程序  
    - 返回原程序或终止  
  - 中断处理和子程序调用的比较  
    - 独立性  
      - 中断处理程序独立于当前程序，由硬件或系统事件触发  
      - 子程序是程序的一部分，由程序员主动调用  
    - 产生方式  
      - 中断由外部设备或异常异步产生  
      - 子程序调用由程序中的调用指令同步产生  
    - 处理机制  
      - 中断处理由操作系统调度执行  
      - 子程序调用由程序控制流直接执行  
    - 入口地址获取  
      - 中断入口地址由中断向量表确定  
      - 子程序入口地址由调用指令直接指定  
    - PC保护方式  
      - 中断发生时，硬件自动保存PC和PSW  
      - 子程序调用时，CALL指令将返回地址压入栈中  
    - 多请求处理  
      - 中断支持嵌套和优先级处理多个请求  
      - 子程序调用按顺序执行，不涉及并发请求  
### 1.3.3    系统调用
- 定义及性质
  - 操作系统提供给应用程序的接口
  - 特殊的公共子程序
  - 与共享资源有关的操作必须通过系统调用
  - 保证系统稳定性和安全性
  - 每个系统调用有唯一调用号
- 功能分类
  - 设备管理
    - 设备请求/释放
    - 设备启动
  - 文件管理
    - 文件读/写
    - 文件创建/删除
  - 进程控制
    - 进程创建/撤销
    - 进程阻塞/唤醒
  - 进程通信
    - 消息传递
    - 信号传递
  - 内存管理
    - 内存分配/回收
    - 获取内存区信息
- 处理过程
  - 第一步
    - 压入调用号和参数
    - 执行陷入指令
    - 用户态→内核态
    - 保护现场
  - 第二步
    - 分析调用类型
    - 查系统调用入口表
    - 执行处理子程序
  - 第三步
    - 恢复/设置CPU现场
    - 返回继续执行
- 运行环境
  - 用户态与内核态切换
  - 通过中断/异常进入内核态
  - 中断返回指令返回用户态
- 用户态→内核态示例
  - 系统调用
  - 中断发生
  - 程序错误
  - 执行特权指令

## 1.4    操作系统结构
### 1.4.1 操作系统结构
- ①. 分层法  

  - 将操作系统分为若干层  
    - 底层（层0）为硬件  
    - 顶层（层N）为用户接口  
    - 每层只能调用紧邻它的低层的功能和服务（单向依赖）  
  - 优点  
    - 便于调试和验证，简化设计实现  
    - 易扩充和维护  
  - 缺点  
    - 合理定义各层困难，依赖关系固定不灵活  
    - 效率较差，需自上而下穿越多层，增加额外开销  

- ②. 模块化  

  - 将操作系统按功能划分为若干独立模块  
    - 每个模块具有某方面管理功能  
    - 规定好模块间接口，用于通信  
  - 模块可进一步细分为子模块  
  - 衡量模块独立性标准  
    - 内聚性：模块内部联系紧密程度  
    - 耦合度：模块间相互影响程度  
  - 优点  
    - 提高正确性、可理解性和可维护性  
    - 增强适应性  
    - 加速开发过程  
  - 缺点  
    - 接口规定难满足实际需求  
    - 设计者齐头并进，难以形成可靠决定顺序  

- ③. 宏内核  

  - 定义：将系统主要功能模块作为一个整体运行在内核态  
  - 特点  
    - 提供高性能系统服务  
    - 各模块共享信息，利用彼此特性  
  - 发展现状  
    - 主流操作系统（如 Windows、Linux、iOS 等）采用  
    - 当前多为融合微内核优点的混合内核  
  - 存在问题  
    - 面临“软件危机”，扩展困难  

- ④. 微内核  

  - (1) 基本概念  
    - 保留最基本功能在内核中  
      - 与硬件处理相关部分  
      - 基本功能  
      - 客户与服务器通信机制  
    - 其他功能移至用户态作为服务器进程运行  
    - 包括进程服务器、设备服务器、文件服务器等  
    - 优点  
      - 高可靠性：错误不会导致系统崩溃  
  - (2) 基本功能  
    - 进程（线程）管理  
      - 通信、切换、调度、同步  
    - 低级存储器管理  
      - 页表机制、地址变换机制  
    - 中断和陷入处理  
      - 捕获中断/陷入事件，发送给相关服务器  
  - (3) 特点  
    - 优点  
      - 扩展性和灵活性  
      - 可靠性和安全性  
      - 可移植性  
      - 支持分布式计算  
    - 缺点  
      - 性能问题：频繁切换用户态与内核态  
      - 改善方式：将常用服务移回内核  

- ⑤. 外核  

  - 不同于虚拟机克隆真实机器  
  - 策略：对资源进行划分  
    - 每个用户分配一个资源子集（如磁盘块范围）  
  - 外核运行在内核态  
    - 分配资源  
    - 检查资源使用的安全性  
  - 用户虚拟机运行自己的操作系统  
    - 限制只能使用已分配资源  
  - 优点  
    - 减少资源映射层  
    - 分离多道程序与用户操作系统  
    - 负载轻，仅需确保资源不冲突  
## 1.5   操作系统引导
### 1.5.1 操作系统引导
- 激活 CPU
  - 读取 ROM 中的 boot 程序

## 1.6    虚拟机
### 1.6.1   虚拟机的基本概念
- 定义
  - 利用虚拟化技术将物理机虚拟化为多台虚拟机
  - 提供抽象的、统一的、模拟的计算环境
- 两类虚拟化方法
  - 第一类虚拟机管理程序
    - 特点
      - 运行在最高特权级
      - 在裸机上运行
      - 提供与裸机硬件相同的虚拟机
    - 运行机制
      - 虚拟内核态模拟
      - 敏感指令处理
        - 支持虚拟化的CPU
        - 不支持虚拟化的CPU
  - 第二类虚拟机管理程序
    - 特点
      - 作为普通进程运行
      - 依赖宿主操作系统
      - 示例: VMware Workstation
    - 运行机制
      - 启动过程
      - 虚拟设备模拟
    - 术语
      - 客户操作系统
      - 宿主操作系统
- 应用场景
  - Web主机领域
    - 共享托管
    - 独占托管
    - 云主机
- 其他称谓
  - 第一类: 裸金属架构
  - 第二类: 寄居架构
