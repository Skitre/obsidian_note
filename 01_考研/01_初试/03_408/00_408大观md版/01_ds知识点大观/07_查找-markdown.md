# 第七章 查找
## 7.1   查找的基本概念
### 7.1.1 查找的基本概念
- 查找
  - 在数据集合中寻找满足某种条件的数据元素的过程
  - 查找结果
    - 查找成功：找到满足条件的数据元素
    - 查找失败：未找到满足条件的数据元素
- 查找表
  - 用于查找的数据集合
  - 由同一类型的数据元素(或记录)组成
  - 常见操作
    - 查询符合条件的数据元素
    - 插入、删除数据元素
- 静态查找表
  - 只涉及查找操作，无须动态修改
  - 适合的查找方法
    - 顺序查找
    - 折半查找
    - 散列查找
- 动态查找表
  - 需要动态插入或删除
  - 适合的查找方法
    - 二叉排序树的查找
    - 散列查找
- 关键字
  - 数据元素中唯一标识该元素的某个数据项的值
  - 查找结果唯一
## 7.2   顺序查找和折半查找
### 7.2.1   顺序查找
- 定义
  - 也称线性查找
  - 适用于顺序表和链表
- 分类
  - 一般线性表的顺序查找
  - 有序线性表的顺序查找
- 一般线性表的顺序查找
  - 基本思想
    - 从线性表一端开始逐个检查关键字
    - 找到则返回位置
    - 查找到另一端未找到则返回失败信息
  - 算法实现
    - 数据结构
      - typedef struct{  } SSTable;         // 定义结构体类型名为 SSTable
      - ElemType *elem; // 指向存储元素的数组的指针  
      - int TableLen;   // 表示该静态查找表的长度  
    - 查找函数
      - int Search_Seq(SSTable ST, ElemType key)
      - 使用哨兵ST.elem[0]
      - 从后往前查找
  - 性能分析
    - 查找成功时
      - 比较次数C₁=n-i+1
      - 平均查找长度ASL成功=(n+1)/2
    - 查找失败时
      - ASL不成功=n+1
  - 优缺点
    - 优点
      - 对存储结构无要求
      - 对记录有序性无要求
    - 缺点
      - n较大时效率低
- 有序线性表的顺序查找
  - 特点
    - 查找失败时可提前返回
    - 降低查找失败的平均查找长度
  - 判定树描述
    - 圆形结点：表中存在的元素
    - 矩形结点（失败结点）：不在表中的数据值
  - 性能分析
    - 查找成功ASL与一般顺序查找相同
    - 查找失败ASL不成功=∑(qj*lj)
      - qj=1/(n+1)
      - lj=失败结点所在层数
  - 注意事项
    - 与折半查找思想不同
    - 可适用于链式存储结构
### 7.2.2   折半查找
- 定义
  - 也称二分查找
  - 仅适用于有序的顺序表
- 基本思想
  - 步骤1：将key与中间元素比较
    - 相等则查找成功
    - 不等则在前半或后半继续查找
  - 步骤2：重复上述过程直到找到或确认不存在
- 算法实现
  - 代码框架：
    - int BinarySearch(SqList L, ElemType key)
    - 使用low、high、mid指针
    - 循环条件：while(low<=high)
  - 关键操作：
    - mid=(low+high)/2
    - 比较L.elem[mid]与key
    - 调整查找范围：high=mid-1或low=mid+1
- 判定树
  - 性质：
    - 圆形结点：有效记录
    - 方形结点：失败区间
    - 满足二叉排序树性质
    - 平衡二叉树（n个非叶结点，n+1个叶结点）
  - 查找长度：
    - 成功：根到目标结点的路径长度
    - 失败：根到失败结点父结点的路径长度
- 性能分析
  - 时间复杂度：O(log₂n)
  - 最大比较次数：不超过树高
  - 平均查找长度：
    - 成功ASL=(1×1+2×2+3×4+4×4)/11=3
    - 失败ASL=(3×4+4×8)/12=11/3
- 适用场景
  - 存储结构要求：
    - 仅适用于顺序存储结构
    - 不支持链式存储
  - 数据要求：
    - 元素必须有序排列
    - 需要随机存取特性
### 7.2.3   分块查找
- 定义
  - 也称索引顺序查找
  - 结合顺序查找和折半查找的优点
  - 既有动态结构又适于快速查找
- 基本思想
  - 将查找表分为若干子块
    - 块内元素可以无序
    - 块间元素有序
      - 第一个块的最大关键字小于第二个块的所有记录关键字
      - 第二个块的最大关键字小于第三个块的所有记录关键字
      - 以此类推
  - 建立索引表
    - 每个元素包含
      - 各块的最大关键字
      - 各块第一个元素的地址
    - 索引表按关键字有序排列
- 查找过程
  - 第一步：在索引表中确定待查记录所在的块
    - 可采用顺序查找或折半查找索引表
  - 第二步：在块内顺序查找
- 平均查找长度(ASL)
  - 公式：ASL = L₁ + Ls
    - L₁：索引查找的平均查找长度
    - Ls：块内查找的平均查找长度
  - 等概率情况下
    - 将长度为n的表均匀分为b块，每块s个记录
    - 块内和索引表均采用顺序查找时：
      - ASL = (b+1)/2 + (s+1)/2
    - 当s=√n时
      - ASL取最小值√n + 1
- 特点
  - 索引表占用额外存储空间
  - 索引查找增加系统开销
  - 优点
    - 块内查找范围较小
    - 总体效率比顺序查找高
## 7.3   树形查找
### 7.3.1   二叉排序树(BST)
- 目的
  - 提高查找、插入和删除关键字的速度
  - 非线性结构有利于插入和删除的实现
- ①. 二叉排序树的定义
  - 定义
    - 空树
    - 或具有以下特性的二叉树
      - 左子树非空 → 左子树上所有结点的值 < 根结点的值
      - 右子树非空 → 右子树上所有结点的值 > 根结点的值
      - 左、右子树也分别是二叉排序树
    - 左子树结点值 < 根结点值 < 右子树结点值
    - 中序遍历 → 递增有序序列
- ②. 二叉排序树的查找
  - 过程
    - 从根结点开始，逐层向下比较
    - 递归过程
  - 非递归查找算法
    - BSTNode *BST_Search(BiTree T,ElemType key)
  - 递归查找算法
    - 执行效率较低
- ③. 二叉排序树的插入
  - 特点
    - 动态树表
    - 查找过程中插入新结点
  - 插入过程
    - 原树为空 → 直接插入
    - 关键字k < 根结点值 → 插入左子树
    - 关键字k > 根结点值 → 插入右子树
    - 新插入的结点是叶结点
  - 算法描述
    - int BST_Insert(BiTree &T,KeyType k)
- ④. 二叉排序树的构造
  - 过程
    - 从空树出发，依次插入元素
  - 算法描述
    - void Creat_BST(BiTree &T,KeyType str[],int n)
- ⑤. 二叉排序树的删除
  - 处理三种情况
    - 被删除结点是叶结点 → 直接删除
    - 只有一棵左子树或右子树 → 子树替代原结点位置
    - 有左、右两棵子树 → 用直接后继(或前驱)替代，再删除该后继(或前驱)
- ⑥. 二叉排序树的查找效率分析
  - 取决于树的高度
  - 平衡二叉树 → 平均查找长度O(log₂n)
  - 最坏情况
    - 输入序列有序 → 单支树
    - 高度为n → 平均查找长度(n+1)/2
  - 与二分查找比较
    - 平均时间性能相似
    - 二叉排序树不唯一，二分查找判定树唯一
  - 应用场景
    - 静态查找表 → 有序顺序表 + 二分查找
    - 动态查找表 → 二叉排序树
### 7.3.2   平衡二叉树
- ①. 平衡二叉树的定义

  - 为避免树高度增长过快，规定插入和删除结点时，任意结点的左右子树高度差绝对值不超过1
  - 平衡因子：结点左子树与右子树的高度差，取值可能为-1、0或1
  - 平衡二叉树性质：
    - 是空树
    - 或左右子树都是平衡二叉树，且左右子树高度差绝对值不超过1

- ②. 平衡二叉树的插入

  - 基本思想：

    - 检查插入路径上的结点是否因操作导致不平衡
    - 若不平衡，找到离插入结点最近的平衡因子绝对值大于1的结点A
    - 对以A为根的子树进行调整，保持二叉排序树特性

  - 调整对象：最小不平衡子树（插入路径上离插入结点最近的平衡因子绝对值大于1的结点为根的子树）

  - 调整规律（4种情况）：

    - 1) LL平衡旋转（右单旋转）

      - 原因：在结点A的左孩子(L)的左子树(L)插入新结点
      - 操作：
        - A的左孩子B向右上旋转代替A成为根结点
        - A向右下旋转成为B的右孩子
        - B的原右子树作为A的左子树

    - 2) RR平衡旋转（左单旋转）

      - 原因：在结点A的右孩子(R)的右子树(R)插入新结点
      - 操作：
        - A的右孩子B向左上旋转代替A成为根结点
        - A向左下旋转成为B的左孩子
        - B的原左子树作为A的右子树

    - 3) LR平衡旋转（先左后右双旋转）

      - 原因：在结点A的左孩子(L)的右子树(R)插入新结点
      - 操作：
        - 先将A的左孩子B的右子树的根结点C向左上旋转提升到B的位置
        - 然后把C向右上旋转提升到A的位置
      - 示例：图7.13

    - 4) RL平衡旋转（先右后左双旋转）

      - 原因：在结点A的右孩子(R)的左子树(L)插入新结点
      - 操作：
        - 先将A的右孩子B的左子树的根结点C向右上旋转提升到B的位置
        - 然后把C向左上旋转提升到A的位置

- ③. 平衡二叉树的删除

  - 步骤：
    - 1) 用二叉排序树的方法删除结点w
    - 2) 若导致不平衡，从w开始向上回溯，找到第一个不平衡的结点z（最小不平衡子树）
    - 3) 对以z为根的子树进行平衡调整（4种情况与插入操作相同）
  - 与插入操作的不同：
    - 插入操作仅需对以z为根的子树进行调整
    - 删除操作可能需要对z的祖先结点进行调整，甚至回溯到根结点

- ④. 平衡二叉树的查找

  - 查找过程与二叉排序树相同
  - 比较次数不超过树的深度
  - 深度为h的平衡二叉树最少结点数：
    - n₀=0, n₁=1, n₂=2
    - nₕ=nₕ₋₂ + nₕ₋₁ + 1
  - 最大深度：O(log₂n)
  - 平均查找效率：O(log₂n)
  - 应用：求解给定结点数的平衡二叉树的最多比较次数或树的最大高度
### 7.3.3   红黑树
- 红黑树的定义
  - 引入原因：AVL树调整频繁代价大，放宽平衡条件
  - 红黑性质：
    - ① 结点颜色：红或黑
    - ② 根结点黑色
    - ③ 叶结点（NULL结点）黑色
    - ④ 无相邻红结点
    - ⑤ 任意结点到叶结点路径黑结点数相同
  - 黑高定义：某结点到叶结点路径的黑结点总数
  - 结论：
    - 最长路径≤最短路径2倍
    - 高度h≤2log₂(n+1)
- 红黑树的插入
  - 基本过程：类似二叉查找树插入，需调整
  - 结论3：新结点初始为红色
  - 插入情况：
    - 情况1：叔结点黑色，z为右孩子（LR）
    - 情况2：叔结点黑色，z为左孩子（LL）
    - 情况3：叔结点红色
  - 调整方法：
    - 情况1：左旋转情况2
    - 情况2：右旋+颜色交换
    - 情况3：父叔变黑，爷变红，z上移两层
- 红黑树的删除
  - 删除情况分类：
    - 只有右/左子树
    - 无孩子且红色
    - 无孩子且黑色（双黑结点处理）
  - 双黑结点调整情况：
    - 情况1：兄弟w红色
    - 情况2：w黑色且右孩子红色（RR）
    - 情况3：w黑色且左孩子红色（RL）
    - 情况4：w黑色且两孩子黑色
  - 调整方法：
    - 情况1：颜色交换+左旋
    - 情况2：颜色交换+左旋+右孩子变黑
    - 情况3：颜色交换+右旋转情况2
    - 情况4：去双重黑色，父结点额外黑色
## 7.4   B树和 B+树
### 7.4.1   B树及其基本操作
- B树的定义
  - m阶B树是所有结点的平衡因子均等于0的m路平衡查找树
  - 空树或满足特定特性的m叉树
- B树的特性
  - 每个结点至多有m棵子树（m-1个关键字）
  - 根结点不是叶结点时至少有2棵子树（1个关键字）
  - 非根非叶结点至少有⌈m/2⌉棵子树（⌈m/2⌉-1个关键字）
  - 非叶结点结构
    - 关键字K₁<K₂<...<Kₙ
    - 指针P₀,P₁,...,Pₙ
      - Pᵢ所指子树关键字均小于Kᵢ
      - Pᵢ₊₁所指子树关键字均大于Kᵢ
    - 关键字个数n满足⌈m/2⌉-1≤n≤m-1
  - 所有叶结点出现在同一层次且不带信息
- 5阶B树实例分析
  - 孩子个数=关键字个数+1
  - 根结点子树个数≥2（若有关键字）
  - 非根非叶结点子树3-5个（关键字2-4个）
  - 关键字有序排列，子树关键字落在区间内
  - 叶结点在第4层表示查找失败
- B树的查找
  - 基本操作
    - 在B树中找结点（磁盘操作）
    - 在结点内找关键字（内存操作）
  - 查找过程
    - 从根结点开始多路分支决定
    - 结点内使用顺序或折半查找
    - 查找到叶结点时表示失败
- B树的高度（磁盘存取次数）
  - 高度不包括叶结点层
  - 最小高度（结点关键字最多时）
    - h≥logₘ(n+1)
  - 最大高度（结点关键字最少时）
    - h≤log⌈m/2⌉((n+1)/2)+1
- B树的插入
  - 操作步骤
    - 定位：找到插入的终端结点
    - 插入：
      - 关键字个数<m：直接插入
      - 关键字个数≥m：分裂结点
  - 分裂方法
    - 取新结点
    - 原结点中间关键字上移至父结点
    - 可能导致树高增加
- B树的删除
  - 非终端结点删除
    - 用前驱或后继替代
    - 转换为终端结点删除
  - 终端结点删除情况
    - 直接删除（关键字个数≥⌈m/2⌉）
    - 兄弟够借（父子换位法）
    - 兄弟不够借（合并结点）
  - 合并操作影响
    - 可能导致父结点关键字减少
    - 可能需要递归调整或合并
    - 根结点关键字为0时删除根
### 7.4.2   B+树的基本概念
- B+树是B树的变形树，用于数据库
- m阶B+树的条件
  - 1) 每个分支结点最多有m棵子树
  - 2) 非叶根结点至少有两棵子树，其他分支结点至少有「m/2]棵子树
  - 3) 结点的子树个数与关键字个数相等
  - 4) 叶结点特征
    - 包含全部关键字及指向记录的指针
    - 关键字按大小顺序排列
    - 相邻叶结点相互链接（支持顺序查找）
  - 5) 分支结点特征
    - 仅包含子结点中关键字的最大值
    - 包含指向子结点的指针
- m阶B+树与m阶B树的主要差异
  - 1) 关键字与子树关系
    - B+树：n个关键字对应n棵子树
    - B树：n个关键字对应n+1棵子树
  - 2) 关键字个数范围
    - B+树
      - 非根内部结点：[m/2]≤n≤m
      - 非叶根结点：2≤n≤m
    - B树
      - 非根内部结点：[m/2]-1≤n≤m-1
      - 根结点：1≤n≤m-1
  - 3) 关键字分布
    - B+树：非叶结点关键字也出现在叶结点
    - B树：终端结点关键字不重复
  - 4) 结点功能
    - B+树
      - 叶结点包含信息
      - 非叶结点仅起索引作用
    - B树：所有结点都包含信息
  - 5) 链表结构
    - B+树：叶结点组成线性链表
    - B树：无此特性
- B+树结构特点
  - 分支结点的关键字是其子树中最大关键字的副本
  - 两个头指针
    - 指向根结点
    - 指向关键字最小的叶结点
  - 支持两种查找运算
    - 从最小关键字开始的顺序查找
    - 从根结点开始的多路查找
- B+树操作特点
  - 查找、插入和删除操作与B树基本类似
  - 查找过程特殊之处
    - 非叶结点关键字等于给定值时继续向下查找
    - 每次查找都是从根结点到叶结点的路径
## 7.5   散列(Hash ) 表
### 7.5.1  散列表的基本概念
- 线性表和树表查找的特点
  - 查找记录需进行一系列关键字比较
  - 记录位置与关键字之间不存在映射关系
  - 查找效率取决于比较次数
- 散列函数（哈希函数）
  - 定义：将关键字映射到对应地址的函数
  - 表示形式：Hash(key)=Addr
  - 地址类型：数组下标、索引或内存地址等
- 冲突与同义词
  - 冲突定义：不同关键字映射到同一地址
  - 同义词定义：发生冲突的不同关键字
  - 散列函数设计要求
    - 尽量减少冲突
    - 必须设计处理冲突的方法
- 散列表（哈希表）
  - 定义：根据关键字直接访问的数据结构
  - 特点：建立关键字与存储地址的直接映射关系
- 散列表查找性能
  - 理想时间复杂度：O(1)
  - 与表中元素个数无关
### 7.5.2   散列函数的构造方法
- 构造散列函数的注意事项
  - 散列函数的定义域必须包含全部关键字，值域范围依赖于散列表大小
  - 散列函数计算出的地址应尽可能均匀分布在整个地址空间
  - 散列函数应尽量简单，能快速计算出任意关键字的散列地址
- 常用散列函数
  - 直接定址法
    - 散列函数形式：H(key)=key 或 H(key)=a×key+b
    - 特点
      - 计算最简单
      - 不会产生冲突
      - 适合关键字分布基本连续的情况
      - 关键字分布不连续时会造成存储空间浪费
  - 除留余数法
    - 散列函数形式：H(key)=key%p
    - 关键点
      - p取不大于表长m的质数
      - 选择好的p使关键字等概率映射到散列空间
    - 特点
      - 最简单、最常用的方法
      - 能有效减少冲突可能性
  - 数字分析法
    - 方法
      - 选取数码分布均匀的若干位作为散列地址
    - 特点
      - 适合已知关键字集合
      - 更换关键字需要重新构造散列函数
  - 平方取中法
    - 方法
      - 取关键字平方值的中间几位作为散列地址
    - 特点
      - 散列地址与关键字的每位都有关系
      - 使散列地址分布比较均匀
      - 适合关键字每位取值不够均匀的情况
- 选择原则
  - 不同情况下不同散列函数性能不同
  - 具体选择取决于关键字集合的情况
### 7.5.3   处理冲突的方法
- 冲突处理基本概念
  - 任何散列函数都无法绝对避免冲突
  - 需要为冲突关键字寻找下一个"空"Hash地址
  - 表示方法：H_i表示第i次探测得到的散列地址
- 开放定址法
  - 定义：空闲地址向同义词和非同义词表项开放
  - 数学公式：H_i = (H(key)+d_i)%m
    - H(key): 散列函数
    - i: 探测次数(1,2,...,k)
    - m: 散列表长
    - d_i: 增量序列
  - 四种增量序列取法：
    - 1) 线性探测法
      - d_i = 1,2,...,m-1
      - 特点：
        - 顺序查看下一个单元
        - 可能造成元素聚集(堆积现象)
    - 2) 平方探测法
      - d_i = 1²,-1²,2²,-2²,...,k²,-k²
      - 要求：
        - k ≤ m/2
        - m必须是4k+3形式的素数
      - 优点：避免堆积问题
      - 缺点：只能探测约一半单元
    - 3) 双散列法
      - d_i = i×Hash₂(key)
      - 使用两个散列函数
      - 公式：H_i = (H(key)+i×Hash₂(key))%m
    - 4) 伪随机序列法
      - d_i = 伪随机数序列
  - 删除注意事项
    - 不能直接物理删除
    - 需要做删除标记(逻辑删除)
    - 多次删除可能导致表看似满实际有空位
- 拉链法(链接法)
  - 基本思想：
    - 同义词存放在同一线性链表
    - 链表头指针存放在散列表对应单元
  - 适用场景：
    - 经常进行插入和删除的情况
### 7.5.4   散列查找及性能分析
- 7.5.4 散列查找及性能分析的应用
  - 散列表查找过程
    - 初始化：Addr=Hash(key)
    - 步骤①
      - 检测查找表中地址为Addr的位置
      - 若无记录：返回查找失败
      - 若有记录：
        - 比较与key的值
        - 若相等：返回查找成功
        - 否则：执行步骤②
    - 步骤②
      - 用处理冲突方法计算"下一个散列地址"
      - 将Addr置为新地址
      - 转入步骤①
  - 关键结论
    - 相同关键字组+相同散列函数 → 不同冲突处理方法 → 不同散列表 → 不同ASL
    - 散列表查找特点
      - 1) 即使有直接映像，仍需要比较过程
        - 仍需用ASL衡量查找效率
      - 2) 查找效率取决于三个因素
        - 散列函数
        - 处理冲突的方法
        - 装填因子α
          - 定义：表的装满程度
          - α=表中记录数n/散列表长度m
          - ASL依赖于α而非直接依赖n或m
          - α越大 → 冲突可能性越大
  - 能力要求
    - 给定条件：
      - 散列表长度
      - 元素个数
      - 散列函数
      - 冲突解决方法
    - 能够：
      - 求出散列表
      - 计算查找成功的ASL
      - 计算查找不成功的ASL
