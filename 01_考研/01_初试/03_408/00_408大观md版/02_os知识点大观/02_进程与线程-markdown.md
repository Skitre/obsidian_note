# 第 2 章 进程与线程
## 2.1   进程与线程 
### 2.1.1   进程的概念和特征
- ①. 进程的概念
  - 多道程序环境下引入进程的原因
    - 程序并发执行失去封闭性
    - 具有间断性及不可再现性
  - 进程定义
    - 进程实体组成
      - 程序段
      - 相关数据段
      - PCB
    - 典型定义
      - 1)正在执行程序的实例
      - 2)程序从磁盘加载到内存后在CPU上的执行过程
      - 3)具有独立功能的程序在数据集合上运行的过程
    - 操作系统中的进程定义
      - 进程实体的运行过程
      - 系统资源分配和调度的独立单位
  - 系统资源理解
    - CPU时间片
    - 存储器时间
    - 其他设备服务时间
- ②. 进程的特征
  - 动态性
    - 最基本的特征
    - 具有生命周期
  - 并发性
    - 重要特征
    - 多个进程同时存在于内存
  - 独立性
    - 独立运行的基本单位
    - 需要PCB支持
  - 异步性
    - 不可预知的推进速度
    - 需要进程同步机制

### 2.1.2    进程的组成
- 定义
  - 进程是一个独立的运行单位
  - 操作系统进行资源分配和调度的基本单位
- 组成部分
  - 进程控制块(PCB)
    - 核心部分
    - 功能
      - 进程创建时新建PCB，常驻内存
      - 进程存在的唯一标志
      - 进程结束时删除
    - 作用
      - 系统通过PCB了解进程状态信息
      - 调度时从PCB获取状态和优先级
      - 保存CPU状态信息和程序数据地址
      - 进程暂停时保存断点CPU环境
    - PCB包含内容
      - 进程描述信息
        - 进程标识符
        - 用户标识符
      - 进程控制和管理信息
        - 进程当前状态
        - 进程优先级
      - 资源分配清单
        - 内存地址空间信息
        - 打开文件列表
        - I/O设备信息
      - 处理机相关信息(CPU上下文)
        - CPU寄存器值
    - PCB组织方式
      - 链接方式
        - 同一状态PCB链接成队列
        - 不同阻塞原因形成多个阻塞队列
      - 索引方式
        - 同一状态组织在索引表中
        - 不同状态对应不同索引表
  - 程序段
    - 能被进程调度程序调度到CPU执行的程序代码段
    - 可被多个进程共享
  - 数据段
    - 程序加工处理的原始数据
    - 程序执行产生的中间或最终结果

### 2.1.3    进程的状态与转换
- 进程的5种状态
  - 基本状态
    - 运行态
      - 定义: 进程正在CPU上运行
      - 特点: 单CPU中每个时刻只有一个进程处于运行态
    - 就绪态
      - 定义: 进程获得了除CPU外的一切所需资源
      - 特点: 排成就绪队列
    - 阻塞态(等待态)
      - 定义: 进程正在等待某一事件而暂停运行
      - 特点: 排成阻塞队列，可能有多个队列
  - 其他状态
    - 创建态
      - 定义: 进程正在被创建，尚未转到就绪态
      - 创建步骤
        - 申请空白PCB
        - 填写控制管理信息
        - 分配运行资源
        - 转入就绪队列
    - 终止态
      - 定义: 进程正从系统中消失
      - 特点: 处理资源释放和回收
- 状态转换
  - 基本状态转换
    - 就绪态 → 运行态
      - 条件: 被调度后获得CPU资源
    - 运行态 → 就绪态
      - 条件: 时间片用完或更高优先级进程就绪
    - 运行态 → 阻塞态
      - 条件: 请求资源或等待事件
      - 特点: 通过系统调用实现
    - 阻塞态 → 就绪态
      - 条件: 等待的事件到来
      - 特点: 被动行为，需要中断处理程序协助
- 状态区分
  - 就绪态与阻塞态的区别
    - 就绪态: 仅缺少CPU
    - 阻塞态: 需要其他资源或等待事件
    - 区分原因: CPU分配频繁，其他资源分配耗时

### 2.1.4   进程控制
- 功能
  - 创建新进程
  - 撤销已有进程
  - 实现进程状态转换
- 原语特点
  - 执行期间不允许中断
  - 不可分割的基本单位
- ①. 进程的创建
  - 父进程与子进程关系
    - 创建者称为父进程
    - 被创建者称为子进程
    - 子进程可继承父进程资源
    - 子进程终止时归还资源
  - 创建进程的操作
    - 终端用户登录系统
    - 作业调度
    - 系统提供服务
    - 用户程序应用请求
  - 创建原语步骤
    - 1) 分配唯一进程标识号，申请空白PCB
    - 2) 分配运行所需资源
    - 3) 初始化PCB
      - 标志信息
      - CPU状态信息
      - CPU控制信息
      - 设置进程优先级
    - 4) 插入就绪队列
- ②. 进程的终止
  - 终止事件
    - 正常结束
    - 异常结束
      - 存储区越界
      - 保护错
      - 非法指令
      - 特权指令错
      - 运行超时
      - 算术运算错
      - I/O故障
    - 外界干预
      - 操作员干预
      - 操作系统干预
      - 父进程请求
      - 父进程终止
  - 终止原语步骤
    - 1) 检索PCB
    - 2) 终止运行状态进程
    - 3) 终止子孙进程（可选）
    - 4) 归还资源
    - 5) 删除PCB
  - 级联终止
    - 父进程终止导致子进程终止
- ③. 进程的阻塞和唤醒
  - 阻塞事件
    - 请求系统资源失败
    - 等待操作完成
    - 新数据未到达
    - 无新任务可做
  - 阻塞原语(Block)步骤
    - 1) 查找对应PCB
    - 2) 运行态→阻塞态
    - 3) 插入等待队列
  - 唤醒事件
    - I/O操作完成
    - 期待数据到达
  - 唤醒原语(Wakeup)步骤
    - 1) 查找等待队列PCB
    - 2) 移出队列，就绪态
    - 3) 插入就绪队列
  - 原语使用规则
    - Block和Wakeup必须成对使用

### 2.1.5    进程的通信
- 进程通信的定义
  - 进程之间的信息交换
  - PV操作是低级通信方式
  - 高级通信方式：高效率传输大量数据
- 高级通信方法
  - ①. 共享存储
    - 存在可直接访问的共享空间
    - 使用同步互斥工具控制读/写
    - 两种方式
      - 低级方式：基于数据结构
      - 高级方式：基于存储区
    - 操作系统职责
      - 提供共享存储空间
      - 提供同步互斥工具
    - 进程空间独立性
      - 需特殊系统调用实现共享
      - 线程自然共享进程空间
    - 类比：大布袋交换物品
  - ②. 消息传递
    - 不存在共享空间时使用
    - 以格式化的消息为单位
    - 发送和接收消息原语
    - 特点
      - 隐藏实现细节
      - 用户透明
      - 广泛应用
    - 两种方式
      - 直接通信方式
        - 直接发送给接收进程
        - 挂载到消息缓冲队列
      - 间接通信方式
        - 通过中间实体（信箱）
        - 广泛应用于网络
    - 类比：写信通过邮差传递
  - ③. 管道通信
    - 特点
      - 特殊共享文件（pipe文件）
      - 先进先出
      - 生产者-消费者模式
    - 协调能力
      - 互斥
      - 同步
      - 确定对方存在
    - Linux中的管道
      - 本质是文件
      - 解决两个问题
        - 限制管道大小（4KB缓冲区）
        - 读写速度差异
      - 继承性
        - 子进程继承父进程管道
      - 特点
        - 一次性读取
        - 单向通信
        - 双向需两个管道
  - ④. 信号
    - 定义
      - 通知进程事件的机制
      - 不同事件对应不同信号类型
    - 信号处理
      - PCB中记录待处理信号
      - 32位int变量表示（Linux）
      - 处理后将位修改为0
      - 阻塞信号记录
    - 信号发送方式
      - 内核发送
        - 检测系统事件
        - 如非法指令发送SIGILL
      - 进程发送
        - 调用kill函数
        - 指定PID和信号序号
    - 信号处理时机
      - 内核态切换到用户态时检查
      - 强制接收并处理
    - 处理方式
      - 默认处理程序
        - 如SIGILL终止进程
      - 自定义处理程序
        - 如输出
### 2.1.6   线程和多线程模型
- 线程的基本概念
  - 引入目的
    - 减小并发执行的时空开销
    - 提高操作系统的并发性能
  - 定义
    - 轻量级进程
    - CPU执行单元
    - 程序执行流的最小单元
  - 组成
    - 线程ID
    - 程序计数器
    - 寄存器集合
    - 堆栈
  - 特点
    - 共享进程资源
    - 独立调度和分派
    - 三种基本状态
      - 就绪
      - 阻塞
      - 运行
- 线程与进程的比较
  - 调度
    - 线程是独立调度单位
    - 线程切换开销小
  - 并发性
    - 进程间和线程间都可并发
  - 拥有资源
    - 进程是资源拥有单位
    - 线程只拥有必要资源
  - 独立性
    - 进程有独立地址空间
    - 线程共享进程资源
  - 系统开销
    - 线程创建/撤销开销小
  - 多处理器支持
    - 多线程可多CPU并行
- 线程的属性
  - 轻型实体
  - 唯一标识符和TCB
  - 可执行相同程序
  - 共享进程资源
  - CPU独立调度单位
  - 生命周期状态变化
- 线程的状态与转换
  - 执行态
  - 就绪态
  - 阻塞态
- 线程的组织与控制
  - 线程控制块(TCB)
    - 线程标识符
    - 寄存器组
    - 运行状态
    - 优先级
    - 专有存储区
    - 堆栈指针
  - 线程的创建
    - 初始化线程
    - 线程创建函数
  - 线程的终止
    - 任务完成终止
    - 异常强制终止
    - 资源释放
- 线程的实现方式
  - 用户级线程(ULT)
    - 用户空间实现
    - 优点
      - 切换开销小
      - 调度算法专用
      - 平台无关
    - 缺点
      - 系统调用阻塞所有线程
      - 不能多CPU并行
  - 内核级线程(KLT)
    - 内核空间实现
    - 优点
      - 多CPU并行
      - 单线程阻塞不影响其他
      - 切换快开销小
    - 缺点
      - 用户态/内核态切换开销
  - 组合方式
    - 结合ULT和KLT优点
    - 克服各自缺点
  - 线程库实现
    - 用户空间库
    - 内核级库
    - 主要线程库
      - POSIX Pthreads
      - Windows API
      - Java
- 多线程模型
  - 多对一模型
    - 多个用户线程映射一个内核线程
    - 优点：高效
    - 缺点：阻塞整个进程
  - 一对一模型
    - 每个用户线程映射一个内核线程
    - 优点：并发能力强
    - 缺点：开销大
  - 多对多模型
    - n用户线程映射m内核线程(n≥m)
    - 优点：平衡并发和开销

## 2.2    CPU 调 度
### 2.2.1   调度的概念 
- 调度的基本概念
  - CPU调度是对CPU进行分配
  - 从就绪队列中选择进程分配CPU
  - 实现进程并发执行
  - CPU调度是多道程序操作系统的基础
- 调度的层次
  - 高级调度(作业调度)
    - 从外存后备队列选择作业
    - 分配内存和I/O设备
    - 建立相应进程
    - 作业调度是内存与辅存之间的调度
    - 多道批处理系统大多配有作业调度
  - 中级调度(内存调度)
    - 提高内存利用率和系统吞吐量
    - 将暂时不能运行的进程调至外存(挂起态)
    - 具备运行条件时重新调入内存
    - 修改状态为就绪态
    - 中级调度是存储器管理中的对换功能
  - 低级调度(进程调度)
    - 从就绪队列中选择进程
    - 分配CPU
    - 最基本的一种调度
    - 所有操作系统都必须配置
    - 调度频率高(几十毫秒一次)
- 三级调度的联系
  - 作业调度为进程活动做准备
  - 进程调度使进程正常活动起来
  - 中级调度处于作业调度和进程调度之间
  - 调度频率比较
    - 作业调度次数少
    - 中级调度次数略多
    - 进程调度频率最高
  - 进程调度是最基本的，不可或缺

### 2.2.2   调度的实现 
- ①. 调度程序(调度器)
  - 组成
    - 1)排队器
      - 功能:将就绪进程排成队列
      - 操作:进程就绪时插入队列
    - 2)分派器
      - 功能:从队列取出进程分配CPU
    - 3)上下文切换器
      - 操作
        - 第一对:保存当前进程上下文→装入分派程序上下文
        - 第二对:移出分派程序→装入新进程上下文
      - 优化方法:使用两组寄存器(内核/用户)
- ②. 调度的时机、切换与过程
  - 应进行调度的情况
    - 1)创建新进程后
    - 2)进程结束/终止后
    - 3)进程阻塞时
    - 4)I/O设备就绪时
    - 其他情况
      - 更紧急任务
      - 时间片用完
  - 不能调度的情况
    - 1)处理中断时
    - 2)原子操作时
  - 进程切换过程
    - 保存原进程现场→恢复新进程现场
- ③. 进程调度的方式
  - 1)非抢占调度方式
    - 特点:进程持续执行直到主动放弃CPU
    - 优点:实现简单、开销小
    - 缺点:不适用于分时/实时系统
  - 2)抢占调度方式
    - 特点:可暂停当前进程分配CPU
    - 抢占原则
      - 优先权
      - 短进程优先
      - 时间片
- ④. 闲逛进程
  - 特点
    - PID=0
    - 优先级最低
    - 无就绪进程时运行
    - 不会被阻塞
- ⑤. 两种线程的调度
  - 1)用户级线程调度
    - 由进程调度程序决定
    - 切换开销小
  - 2)内核级线程调度
    - 由内核直接选择线程
    - 切换开销大(完整上下文切换)

### 2.2.3    调度的目标 
- 1) CPU利用率
  - 计算方法
    - CPU利用率 = (CPU有效工作时间)/(CPU总工作时间)[^1]
- 2) 系统吞吐量
  - 定义：单位时间内CPU完成作业的数量[^2]
  - 影响因素
    - 长作业会降低吞吐量
    - 短作业能提高吞吐量
    - 调度算法和方式的影响[^2]
- 3) 周转时间
  - 定义：作业提交到完成所经历的时间[^2]
  - 计算公式
    - 周转时间=作业完成时间-作业提交时间[^2]
    - 平均周转时间=(作业1周转时间+...+作业n周转时间)/n[^2]
    - 带权周转时间=周转时间/作业实际运行时间[^2]
    - 平均带权周转时间=(作业1带权周转时间+...+作业n带权周转时间)/n[^2]
- 4) 等待时间
  - 定义：进程等待CPU的时间之和[^2]
  - 调度算法主要影响等待时间[^2]
- 5) 响应时间
  - 定义：用户提交请求到系统首次响应的时间[^2]
  - 交互式系统的重要评价标准[^2]
- 调度程序设计考虑因素
  - 满足特定用户要求（如实时/交互进程的快速响应）[^2]
  - 考虑系统整体效率（如减少平均周转时间）[^2]
  - 考虑调度算法开销[^2]

### 2.2.4   进程切换 
- 进程运行特点
  - 进程创建、撤销、I/O操作通过系统调用进入内核
  - 进程切换在内核支持下实现
  - 所有进程都在操作系统内核支持下运行
- (1)上下文切换
  - 定义
    - 保存当前进程状态并恢复另一个进程状态
    - 进程上下文用PCB表示
      - CPU寄存器值
      - 进程状态
      - 内存管理信息
  - 切换流程
    1) 挂起进程，保存CPU上下文到PCB
    2) 将PCB移入相应队列
    3) 选择另一个进程执行，更新其PCB
    4) 恢复新进程CPU上下文
    5) 跳转到新进程程序计数器位置
- (2)上下文切换的消耗
  - 计算密集型操作
  - 每次切换需要纳秒级时间
  - 消耗大量CPU时间
  - 优化方法
    - 使用多寄存器组CPU
    - 只需改变寄存器组指针
- (3)上下文切换与模式切换
  - 模式切换特点
    - CPU逻辑上可能执行同一进程
    - 用户态和内核态之间的切换
    - 不改变当前进程
  - 上下文切换特点
    - 只能发生在内核态
    - 多任务操作系统的必需特性
  - 调度与切换区别
    - 调度：决策行为（决定资源分配）
    - 切换：执行行为（实际分配）
    - 顺序：先调度后切换

### 2.2.5    典型的调度算法 
- 先来先服务 (FCFS) 调度算法
  - 思想
    - 作业调度
    - 进程调度

## 2.3    同步与互斥
### 2.3.1    同步与互斥的基本概念 
- ①. 临界资源
  - 定义：一次仅允许一个进程使用的资源
  - 示例：打印机、共享变量和数据
  - 临界区
    - 定义：进程中访问临界资源的代码段
    - 访问过程四个部分
      - 进入区：检查并设置访问标志
      - 临界区：实际访问临界资源的代码
      - 退出区：清除访问标志
      - 剩余区：代码其余部分
  - 代码示例
    c
    while(true){
        entry section;       //进入区
        critical section;    //临界区
        exit section;        //退出区
        remainder section;   //剩余区
    }
    
- ②. 同步
  - 定义：直接制约关系
  - 特点
    - 为完成共同任务建立
    - 需要协调运行次序
    - 通过等待、传递信息实现
  - 示例：单缓冲区的输入输出进程
- ③. 互斥
  - 定义：间接制约关系
  - 特点
    - 一个进程使用临界资源时其他进程必须等待
    - 使用完毕后允许其他进程访问
  - 示例：打印机共享系统
- 临界区互斥准则
  ①. 空闲让进
  ②. 忙则等待
  ③. 有限等待
  ④. 让权等待（非必须）
### 2.3.2    实现临界区互斥的基本方法 
- 软件实现方法
  - 算法一：单标志法
    - 公用整型变量turn指示允许进入临界区的进程编号
    - 进程退出临界区时将临界区的使用权赋予给另一个进程
    - 缺点
      - 必须交替进入临界区
      - 违背“空闲让进”准则
  - 算法二：双标志先检查法
    - 布尔型数组flag[2]标记各个进程想进入临界区的意愿
    - 先检查对方标志，再设置自己的标志
    - 缺点
      - 可能同时进入临界区
      - 违背“忙则等待”准则
  - 算法三：双标志后检查法
    - 先设置自己的标志，再检查对方的标志
    - 缺点
      - 可能导致"饥饿"现象
      - 违背"空闲让进"和"有限等待"准则
  - 算法四：Peterson算法
    - 结合flag[]和turn变量
    - 遵循准则
      - "空闲让进"
      - "忙则等待"
      - "有限等待"
    - 缺点
      - 未遵循"让权等待"准则
- 硬件实现方法
  - 中断屏蔽方法
    - 关中断保证当前进程临界区代码顺利执行
    - 缺点
      - 限制CPU交替执行能力
      - 系统效率降低
  - TestAndSet指令
    - 原子操作测试并设置锁变量
    - 缺点
      - 等待进程占用CPU
      - 不能实现"让权等待"
  - Swap指令
    - 原子交换两个变量的值
    - 优点
      - 简单
      - 适用于多处理器系统
    - 缺点
      - 不能实现"让权等待"
      - 可能导致"饥饿"现象

### 2.3.4   信号量
- 信号量
  - 定义
    - 用于解决互斥与同步问题的机制
    - 只能被两个标准原语访问
      - wait()/P()
      - signal()/V()
  - 原语特性
    - 不可分割的操作序列
    - 实现方式
      - 硬件实现
      - 软件通过屏蔽中断实现

  - 信号量类型
    - 整型信号量
      - 定义
        - 表示资源数量的整型量S
      - 操作
        - 初始化
        - wait(S)
          ```
          while(S<=0);
          S=S-1;
          ```
        - signal(S)
          ```
          S=S+1;
          ```
      - 缺点
        - 忙等状态
        - 不遵循"让权等待"准则

    - 记录型信号量
      - 数据结构
        ```
        typedef struct{
          int value;
          struct process *L;
        }semaphore;
        ```
      - wait(S)操作
        ```
        S.value--;
        if(S.value<0){
          add this process to S.L;
          block(S.L);
        }
        ```
      - signal(S)操作
        ```
        S.value++;
        if(S.value<=0){
          remove a process P from S.L;
          wakeup(P);
        }
        ```
      - 优点
        - 避免忙等
        - 遵循"让权等待"准则

  - 信号量应用
    - 实现进程互斥
      - 设置互斥信号量S（初值为1）
      - 临界区代码结构
        ```
        P(S);
        // 临界区代码
        V(S);
        ```
      - 注意事项
        - 不同资源需要不同信号量
        - P/V必须成对出现
        - 多个资源时信号量初值设为资源数量

    - 实现进程同步
      - 设置同步信号量S（初值为0）
      - 典型模式
        ```
        // 生产者
        执行操作x;
        V(S);
      
        // 消费者
        P(S);
        执行操作y;
        ```

    - 实现前驱关系
      - 为每对前驱关系设置同步信号量（初值为0）
      - 在前驱操作后执行V
      - 在后继操作前执行P
      - 示例
        ```
        // S1→S2→S4→S6
        // S1→S3→S6
        // S2→S5→S6
        semaphore a12=0, a13=0, a24=0, a25=0, a36=0, a46=0, a56=0;
      
        S1(){
          ...;
          V(a12); V(a13);
        }
        S2(){
          P(a12);
          ...;
          V(a24); V(a25);
        }
        // 其他类似
        ```

  - 分析方法
    - 关系分析
      - 确定进程数量
      - 分析同步/互斥关系
    - 整理思路
      - 确定P/V操作顺序
    - 设置信号量
      - 确定信号量类型和初值
      - 完善代码结构

## 2.4    死 锁
### 2.4.1    死锁的概念
- ①. 死锁的定义
  - 多道程序系统中进程并发执行导致死锁
  - 死锁：多个进程因竞争资源造成的僵局（互相等待对方资源）
  - 示例
    - 生活实例：窄桥上的两辆汽车互不相让
    - 计算机实例：P1占用输入设备请求打印机，P2占用打印机请求输入设备
- ②. 死锁与饥饿
  - 死锁：组内每个进程都在等待组内另一个进程产生的事件
  - 饥饿：进程在信号量内无穷等待
    - 产生原因：不公平的资源分配策略
    - 示例：短文件优先打印策略导致长文件饥饿
  - 共同点：进程无法顺利推进
  - 主要差别
    - 饥饿进程数≥1，死锁进程数≥2
    - 饥饿进程可能处于就绪态或阻塞态，死锁进程必定处于阻塞态
- ③. 死锁产生的原因
  - (1)系统资源的竞争
    - 不可剥夺资源（如打印机）数量不足
    - 可剥夺资源（如CPU）不会引起死锁
  - (2)进程推进顺序非法
    - 请求和释放资源顺序不当
    - 信号量使用不当
    - 进程相互等待对方消息
- ④. 死锁产生的必要条件
  - 1)互斥条件：资源排他性使用
  - 2)不可剥夺条件：资源只能由持有进程主动释放
  - 3)请求并保持条件：持有资源同时请求新资源
  - 4)循环等待条件：存在进程资源的循环等待链
    - 注意：循环等待是必要条件非充分条件
    - 同类资源数>1时含圈不一定死锁
    - 每类资源=1时含圈等价于死锁
- ⑤. 死锁的处理策略
  - 1)死锁预防：破坏必要条件
    - 限制严格，实现简单，效率低
  - 2)避免死锁：防止进入不安全状态
    - 限制宽松，实现复杂
  - 3)死锁检测及解除：允许死锁发生后处理


### 2.4.2    死锁预防
- 基本概念
  - 预防死锁的发生只需破坏死锁产生的4个必要条件之一即可
- 破坏互斥条件
  - 方法
    - 将互斥使用的资源改造为允许共享使用
  - 缺点
    - 有些资源不能同时访问
    - 破坏互斥条件不太可行
- 破坏不可剥夺条件
  - 方法
    - 进程请求新资源得不到满足时必须释放已保持的所有资源
  - 缺点
    - 实现复杂
    - 可能造成前一阶段工作失效
    - 适用于易保存恢复的资源
    - 影响进程推进速度
    - 增加系统开销
- 破坏请求并保持条件
  - 方法1：预先静态分配
    - 进程运行前一次申请全部资源
    - 缺点
      - 系统资源浪费
      - 可能导致饥饿
  - 方法2：逐步释放
    - 进程运行初期获得资源后开始运行
    - 使用完毕后释放资源才能请求新资源
    - 优点
      - 改进方法1的缺点
- 破坏循环等待条件
  - 方法：顺序资源分配法
    - 给资源编号
    - 按编号递增顺序请求资源
    - 同类资源一次申请完
  - 缺点
    - 编号必须稳定
    - 不便于增加新设备
    - 可能造成资源浪费
    - 给用户编程带来麻烦

### 2.4.3   死锁避免 
- 定义
  - 事先预防策略
  - 每次分配资源时分析死锁风险
  - 不破坏死锁必要条件
- 系统安全状态
  - 安全状态定义
    - 存在安全序列(P₁,P₂,...,Pn)
    - 每个进程都能顺利完成
  - 不安全状态定义
    - 无法找到安全序列
  - 安全状态与死锁关系
    - 安全状态不会死锁
    - 不安全状态可能死锁
- 银行家算法
  - 基本思想
    - 类比银行家贷款
    - 进程预先声明最大需求
  - 数据结构
    - Available向量
    - Max矩阵
    - Allocation矩阵
    - Need矩阵(Need=Max-Allocation)
  - 算法步骤
    ①. 检查Request≤Need
    ②. 检查Request≤Available
    ③. 试探分配并修改数据结构
    ④. 执行安全性算法
  - 安全性算法
    ①. 初始化Work=Available
    ②. 寻找Need≤Work的进程
    ③. 加入安全序列并释放资源
    ④. 检查是否所有进程都在安全序列

### 2.4.4    死锁检测和解除 
- 死锁检测
  - 与死锁避免的对比
    - 死锁避免：需要知道进程从开始到结束的所有资源请求
    - 死锁检测：只需知道对应时刻的资源请求
  - 资源分配图检测法
    - 图形表示
      - 圆圈表示进程
      - 框表示一类资源
      - 框中的圆表示一个资源
    - 边类型
      - 请求边：进程→资源
      - 分配边：资源→进程
  - 资源分配图简化方法
    - 步骤1：找出可运行进程
      - 条件：申请资源≤空闲资源
      - 操作：消去该进程所有边
    - 步骤2：释放资源唤醒阻塞进程
    - 死锁定理：当且仅当图不可完全简化
- 死锁解除
  - 资源剥夺法
    - 挂起部分死锁进程
    - 抢占资源分配给其他进程
  - 撤销进程法
    - 强制撤销部分/全部死锁进程
    - 按优先级和撤销代价选择
  - 进程回退法
    - 回退到回避死锁的状态
    - 要求：保存历史信息和还原点
